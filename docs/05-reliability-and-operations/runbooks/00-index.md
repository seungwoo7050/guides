# 운영 런북 색인

이 디렉터리는 공개 단일 호스트 서비스에서 반복 가능성이 높은 장애를 **증상에서 시작하는 절차**로 정리합니다. 각 런북은 원인을 미리 단정하지 않습니다. 먼저 사용자 영향과 관찰 사실을 확인하고 비용이 낮은 검사부터 실패 경계를 좁힌 뒤 되돌릴 수 있는 완화를 우선합니다.

## 사용 규칙

1. 현재 시각, 환경, 릴리스와 최초 증상을 기록합니다.
2. 동시에 여러 설정을 바꾸지 않습니다.
3. 명령을 실행하기 전에 대상 호스트·Compose 프로젝트·서비스를 다시 확인합니다.
4. 데이터 삭제, 볼륨 제거, 방화벽 전체 교체, 자격 증명 폐기는 명시된 승인 경계에서만 수행합니다.
5. 완화 뒤에는 내부 상태가 아니라 외부 사용자 경로로 복구를 확인합니다.
6. 명령과 UI가 바뀌면 런북을 즉시 수정하고 다음 훈련에서 다시 검증합니다.

## 공통 준비 정보

런북을 사용하기 전에 다음 값을 안전한 운영 위치에서 확인합니다.

```text
환경 이름
공개 hostname
host 또는 instance ID
Compose project directory
현재 release manifest
이전 호환 release manifest
관측 dashboard와 log 위치
backup manifest 위치
incident communication 경로
```

실제 비밀값은 런북이나 사고 타임라인에 복사하지 않습니다.

## 공통 중단 조건

다음 상황에서는 자동화나 개인 판단으로 계속 진행하지 않고 사고 지휘자 또는 데이터·보안 소유자에게 에스컬레이션합니다.

- 데이터 파괴 또는 정합성 위반 가능성이 있습니다.
- 현재와 이전 릴리스가 모두 호환되지 않습니다.
- 호스트나 CI가 공격자에게 장악됐을 가능성이 있습니다.
- 백업과 복호화 키의 무결성을 신뢰할 수 없습니다.
- DNS·레지스트리·비밀값 원본의 관리 권한이 불분명합니다.
- 같은 조치를 반복했는데 결과가 달라집니다.
- 증거 보존과 사용자 영향 완화가 충돌합니다.

## 공통 복구 확인

```text
외부 DNS
→ TCP 443
→ TLS hostname·chain
→ Gateway
→ Application readiness
→ 핵심 읽기
→ 안전한 쓰기와 재조회
→ Background 처리
→ Error·latency 안정화
→ 경보 정상화
```

경보가 사라졌다는 사실만으로 복구를 확정하지 않습니다. 경보 수집 자체가 실패했을 수 있습니다.
