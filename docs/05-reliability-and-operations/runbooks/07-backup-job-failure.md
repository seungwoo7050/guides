# 런북: 백업 작업 실패

## 대상 증상과 사용자 영향

- 정기 백업 작업이 실패하거나 백업 경과 시간 경보가 발생합니다.
- 서비스가 아직 정상이어도 RPO를 충족하지 못할 위험이 커집니다.
- 빈 파일이나 외부로 전송되지 않은 로컬 산출물을 성공한 백업으로 오인할 수 있습니다.

## 사전 안전 조건

- 마지막으로 검증된 백업과 매니페스트를 삭제하거나 덮어쓰지 않습니다.
- 실패한 스테이징 산출물을 현재 백업으로 승격하지 않습니다.
- 복호화 키와 DB 자격 증명을 로그에 출력하지 않습니다.

## 1. 현재 RPO 위험 계산

다음을 기록합니다.

```text
마지막 외부 저장·검증 성공 백업 시각
복원 시험에서 확인한 최신 데이터 시각
현재 시각
계약 RPO
```

단순히 백업 작업이 실행된 시각이 아니라 실제 외부 산출물과 검증 결과를 기준으로 판단합니다.

## 2. 단계별 실패 위치 확인

```text
DB 스냅샷·덤프
→ 산출물 크기·내용 검사
→ 압축
→ 암호화
→ 체크섬·매니페스트
→ 외부 업로드
→ 원격 검증
→ 보존 정책 적용
→ 지표·경보 갱신
```

각 단계의 종료 코드와 임시 파일을 확인합니다. 셸 파이프라인에서 앞 단계의 실패가 뒤 단계의 성공으로 가려지지 않았는지도 확인합니다.

## 3. 자원 확인

```sh
df -h
df -i
```

- 스테이징 디스크와 inode
- DB 연결·잠금 상태
- CPU·I/O 부하
- 외부 저장소 할당량·네트워크
- 암호화 키 접근 가능 여부
- 시간 동기화

## 4. 원인 분기

### DB 덤프 실패

- DB 상태, 권한, 트랜잭션 일관성 옵션을 확인합니다.
- 스키마 업그레이드 뒤 백업 도구의 호환성을 확인합니다.
- 실행 중인 데이터 디렉터리를 일반 파일 복사로 대체하지 않습니다.

### 산출물이 비어 있거나 불완전함

- 예상 테이블·행·객체 메타데이터 검사를 추가합니다.
- 임시 파일을 현재 백업 이름으로 바꾸지 않습니다.

### 암호화·체크섬 실패

- 키 접근과 도구 버전을 확인합니다.
- 평문 산출물이 스테이징에 머무는 시간을 최소화합니다.
- 실패했다고 암호화를 생략한 채 외부로 전송하지 않습니다.

### 외부 업로드 실패

- 네트워크, 자격 증명의 권한 범위, 객체 저장소 할당량과 공급자 오류를 확인합니다.
- 횟수가 제한된 재시도와 명확한 타임아웃을 사용합니다.
- 로컬 스테이징 사본만 남았다면 호스트 손실 시 함께 잃을 위험을 명시합니다.

### 보존 정책 적용 실패

- 삭제 권한과 객체 잠금 정책을 확인합니다.
- 최신 백업 실패가 이전의 정상 백업 삭제로 이어지지 않도록 생성·검증과 보존 처리를 분리합니다.

## 5. 가역적 완화

- 원인을 수정한 뒤 새 백업 ID로 다시 실행합니다.
- RPO 초과가 임박하면 비필수 대규모 쓰기나 배치 작업을 제한할지 데이터 소유자와 결정합니다.
- 외부 저장소 장애라면 승인된 두 번째 독립 저장소를 사용합니다.

같은 백업 ID로 불완전한 산출물을 덮어쓰지 않습니다.

## 6. 복구 확인

- 새 산출물이 비어 있지 않습니다.
- 매니페스트의 크기와 체크섬이 실제 산출물과 일치합니다.
- 외부 객체를 검증했습니다.
- 별도의 빈 환경에서 복원 스모크 테스트가 성공합니다.
- 백업 경과 시간 지표가 실제 성공 시각으로 갱신됩니다.
- 실패 경보가 해제되고 테스트 알림도 정상적으로 전달됩니다.

## 7. 증거와 후속 작업

```text
마지막 성공·실패 백업 ID
실패 단계와 종료 코드
RPO 위험 시간
새 산출물 매니페스트·체크섬
외부 저장 검증 결과
복원 스모크 테스트 결과
재시도·할당량·디스크·경보 개선 사항
```
