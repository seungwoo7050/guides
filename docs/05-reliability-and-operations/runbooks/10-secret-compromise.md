# 런북: 비밀값·자격 증명 유출

## 대상 상황과 위험

- 비밀값이 Git, CI 로그, 애플리케이션 로그, 지원 번들 또는 공개 산출물에 노출됐습니다.
- 호스트, CI 또는 관리자 장치 침해로 자격 증명이 탈취됐을 가능성이 있습니다.
- 노출된 파일을 삭제해도 이미 복제된 값을 회수할 수 없습니다.

## 최우선 원칙

> 이력 정리보다 자격 증명 폐기와 영향 범위 제한이 먼저입니다.

손상 가능성이 있는 호스트나 CI에서 새 비밀값을 생성하지 않습니다. 신뢰할 수 있는 별도 장치와 관리 경로를 사용합니다.

## 1. 사고 범위와 시각 고정

값 자체는 기록하지 않고 다음 정보만 남깁니다.

```text
비밀값 이름·버전·권한 범위
최초 노출 가능 시각
발견 시각
노출 위치와 접근 가능 주체
사용한 서비스·환경
관련 감사 로그 보존 위치
```

## 2. 자격 증명 종류별 즉시 조치

### DNS API 토큰

- 별도의 신뢰할 수 있는 관리 경로에서 토큰을 폐기합니다.
- 현재 DNS 레코드와 변경 이력을 저장합니다.
- 필요한 존·레코드에만 접근할 수 있는 최소 권한 토큰을 새로 발급합니다.

### 레지스트리·CI 자격 증명

- push·delete 권한을 즉시 제한합니다.
- 최근 태그, 다이제스트, attestation 변경을 조사합니다.
- 운영 환경은 신뢰가 확인된 정확한 다이제스트만 유지합니다.

### 데이터베이스 자격 증명

- 새 버전을 DB에 추가하고 별도 연결로 검증합니다.
- 소비자를 새 자격 증명으로 전환한 뒤 이전 값을 폐기합니다.
- 무단 쿼리와 데이터 반출 흔적을 조사합니다.

### 세션·서명 키

- 키 회전이 기존 세션을 어떻게 무효화하는지 확인합니다.
- 필요하면 모든 세션을 폐기하고 사용자 재인증을 요구합니다.
- 토큰 유효 기간 동안 발생할 수 있었던 오용 범위를 평가합니다.

### 백업 암호화 키

- 백업 기밀성에 미친 영향과 접근 로그를 조사합니다.
- 새 백업은 새 키로 생성합니다.
- 기존 백업을 재암호화할지, 보존하거나 폐기할지 정책에 따라 결정합니다.

## 3. 호스트·CI 신뢰 판단

공격자가 호스트 root, Docker daemon 또는 CI 워크플로를 제어했을 가능성이 있다면 비밀값 교체만으로 충분하지 않습니다.

- 깨끗한 호스트 재구축
- 워크플로와 고정된 action 검토
- 레지스트리 provenance·다이제스트 검증
- 공격 이전 시점의 백업 선택
- 관리자 SSH 키·OIDC 신뢰 정책·배포 토큰 회전

현재 호스트의 로그와 체크섬을 유일한 증거로 신뢰하지 않습니다.

## 4. 안전한 회전 순서

```text
새 자격 증명 생성
→ 최소 권한 범위 적용
→ 후보 소비자 검증
→ 원자적 전환
→ 모든 replica·worker 확인
→ 이전 자격 증명 폐기
→ 이전 값 사용 시도 탐지
```

단, 공격자가 즉시 악용할 수 있는 고위험 자격 증명은 서비스 중단을 감수하고 먼저 폐기할 수 있습니다. 사고 지휘자와 보안 소유자가 판단합니다.

## 5. Git·로그·산출물의 잔존 데이터 처리

자격 증명을 폐기한 뒤 다음을 수행합니다.

- Git 이력 재작성 필요성 판단
- fork·clone·cache는 회수할 수 없음을 기록
- CI 로그와 산출물 접근 제한·삭제
- 로그 저장소의 보존, 법적 증거와 개인정보 정책 조정
- 비밀값 스캐너와 pre-commit·CI 게이트 추가

이력 재작성은 이미 노출된 자격 증명을 다시 안전한 값으로 만들지 않습니다.

## 6. 사용자·법적 영향

- 어떤 데이터와 계정에 접근할 수 있었는가?
- 실제 무단 사용 증거가 있는가?
- 개인정보·계약·규제상 통지 의무가 있는가?
- 사용자 비밀번호나 세션을 재설정해야 하는가?

확인되지 않은 안전성을 단정하지 않습니다.

## 7. 복구 확인

- 이전 자격 증명이 실제로 거부됩니다.
- 모든 소비자가 새 버전을 사용합니다.
- 레지스트리, DNS, DB, 백업의 변경 이력을 검토했습니다.
- 새 이미지와 릴리스 provenance를 신뢰할 수 있습니다.
- 비밀값이 로그, 지표, 트레이스에 남지 않습니다.
- 새 자격 증명의 권한 범위와 유효 기간을 최소화했습니다.
- 재유출 탐지와 경보가 작동합니다.

## 8. 증거와 후속 작업

```text
비밀값 이름·버전, 값 제외
노출 가능 기간·접근 범위
폐기·발급·전환 시각
영향 조사 결과
신뢰 재설정 범위
사용자 통지 결정
스캐너·권한 범위·회전 개선 사항
```
