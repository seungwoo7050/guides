# 런북: 컨테이너 재시작 반복

## 대상 증상과 사용자 영향

- 컨테이너가 반복해서 `restarting` 또는 `exited` 상태가 됩니다.
- 재시작 정책이 최초 오류를 빠르게 덮을 수 있습니다.
- 애플리케이션, 게이트웨이, DB 중 어느 서비스인지에 따라 영향이 다릅니다.

## 사전 안전 조건

- 반복 재시작 횟수를 늘리거나 모든 서비스를 동시에 재시작하지 않습니다.
- 실패 컨테이너의 inspect, 종료 코드, 최초 로그를 먼저 보존합니다.
- 볼륨과 DB 데이터를 삭제하지 않습니다.

## 1. 상태와 종료 이유 확인

```sh
cd /srv/example
docker compose ps -a
docker inspect '<container>' --format \
  '{{json .State}}'
docker compose logs --tail 200 --no-color '<service>'
```

확인:

- 종료 코드와 시그널
- `OOMKilled`
- 시작·종료 시각
- 상태 검사 실패인지 프로세스 종료인지
- 오류 메시지의 최초 발생 지점
- 재시작 횟수

## 2. 실행 산출물과 설정 확인

```sh
docker inspect '<container>' --format '{{.Image}}'
docker inspect '<container>' --format '{{json .Config.Labels}}'
docker compose config >/dev/null
```

릴리스 매니페스트의 예상 다이제스트와 실제 이미지를 비교합니다. 환경변수 전체를 출력하지 않고 필요한 공개 설정 이름과 비밀값 마운트 존재 여부만 확인합니다.

## 3. 원인 분기

### OOMKilled

- 호스트 메모리, 컨테이너 제한, 런타임 heap을 비교합니다.
- 최근 트래픽·워커·batch 변경을 확인합니다.
- 메모리 누수인지 정상적인 순간 사용량인지 구분합니다.
- 제한 제거보다 입력 제한·워커 축소·호환 롤백을 우선 검토합니다.

### 설정·비밀값 누락

- 릴리스가 요구하는 설정 스키마와 비밀값 버전을 확인합니다.
- 파일 소유자·권한과 마운트 경로를 검사합니다.
- 비밀값은 출력하지 않습니다.

### DB 스키마 비호환

- 현재 스키마 버전과 이미지 허용 범위를 비교합니다.
- 마이그레이션을 반복 실행하지 않습니다.
- 이전 릴리스로 롤백할 수 있는지 매니페스트로 확인합니다.

### 포트·권한 오류

- 프로세스 실행 사용자, 바인드 포트, 쓰기 가능 경로와 읽기 전용 파일 시스템을 확인합니다.
- root로 임시 실행해 문제를 숨기지 않습니다.

### 상태 검사만 실패

프로세스와 실제 프로토콜은 정상인데 상태 검사가 잘못됐을 수 있습니다. 검사 명령, 도구 존재, 경로, 타임아웃, start period를 확인합니다.

## 4. 재시작 폭주 제한

반복 시작이 의존성과 로그를 압박하면 영향받는 서비스만 일시 중지할 수 있습니다.

```sh
docker compose stop '<service>'
```

중지 전에 현재 사용자 영향과 대체 경로를 확인합니다. DB 복구 중인 컨테이너를 무작정 중지하지 않습니다.

## 5. 가역 완화

- 호환되는 이전 정확한 다이제스트로 롤백
- 잘못된 공개 설정·비밀값 포인터 복구
- 검증된 자원 제한·워커 수로 복귀
- 잘못된 상태 검사만 수정

후보 버전을 별도 프로젝트 이름 또는 격리 환경에서 실행해 시작 과정을 확인한 뒤 운영 환경을 바꿉니다.

## 6. 복구 확인

- 재시작 횟수가 더 이상 증가하지 않습니다.
- 프로세스와 프로토콜 상태가 모두 정상입니다.
- 외부 핵심 경로가 성공합니다.
- 메모리·CPU·디스크가 안정됩니다.
- 실제 이미지 다이제스트와 릴리스 기록이 일치합니다.
- 최초 오류 원인을 재현하는 검사가 추가됩니다.

## 7. 증거와 후속 작업
