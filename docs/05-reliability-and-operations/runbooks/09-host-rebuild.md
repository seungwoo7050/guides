# 런북: 호스트 전체 재구축

## 대상 상황

- 기존 호스트에 접근할 수 없거나 더 이상 신뢰할 수 없습니다.
- 기존 로컬 컨테이너, 볼륨, 셸 이력과 인증서를 복구 원본으로 사용할 수 없습니다.
- 외부 레지스트리, Git, 비밀값 원본, DNS 권한과 백업만 사용합니다.

이 런북의 상세 단계와 평가 기준은 [18 공개 서비스 재구축 최종 실습](../18-production-rebuild-capstone.md)을 따릅니다.

## 사전 결정

```text
실제 사고인지 계획된 훈련인지
기존 호스트를 신뢰할 수 있는지
선택 릴리스와 백업
RTO·RPO 목표
새 공개 IP
유지보수·상태 공지 방식
작업자와 승인자
```

## 실행 단계

1. 복구를 선언하고 단계별 시각을 기록합니다.
2. 새 Linux 호스트, 관리 경로, 시간 동기화와 디스크를 검증합니다.
3. Docker Engine·Compose와 방화벽을 준비합니다.
4. 정확한 릴리스 매니페스트와 이미지 다이제스트를 검증합니다.
5. 버전이 명시된 비밀값을 안전하게 주입합니다.
6. 백업 체크섬을 검증하고 복호화한 뒤 격리된 환경에 복원합니다.
7. 내부 애플리케이션 스모크 테스트를 수행합니다.
8. 게이트웨이와 공개 TLS를 준비합니다.
9. A·AAAA 레코드를 확인하고 DNS를 전환합니다.
10. 외부 읽기와 안전한 쓰기를 검증합니다.
11. 로그, 지표와 경보를 연결합니다.
12. 실제 RPO·RTO를 기록합니다.
13. 잘못된 릴리스, 손상된 백업, 누락된 비밀값 실패 훈련을 수행합니다.
14. 기존 자산과 자격 증명을 폐기합니다.

## 금지 사항

- `latest` 태그 사용
- 운영 호스트에서 소스 빌드
- 기존 호스트 파일의 즉석 복사에 의존
- 검증 전에 DNS 전환
- `curl -k` 성공만으로 TLS 완료 판정
- 백업 원본 덮어쓰기
- 증거 문서에 비밀값 기록
