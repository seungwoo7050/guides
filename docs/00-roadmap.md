# Python 가이드 로드맵

## 학습 목표

이 가이드는 Python 문법을 한 번 훑는 데서 끝나지 않습니다. 다음 개발 과정을 스스로 반복할 수 있는 수준에 도달하는 것이 목표입니다.

```text
작은 동작 규칙을 정한다
→ Python 코드로 구현한다
→ 파일·프로세스·시간 같은 외부 의존성을 분리한다
→ 실패 조건과 경곗값을 자동으로 검사한다
→ 결과를 재현 가능한 형태로 남긴다
```

이 저장소에서 Python은 다음 두 가지 용도로 사용합니다.

1. 반복 작업과 검증 절차를 구현하는 자동화 언어
2. 운영체제·네트워크·컴퓨터 구조·알고리즘 가이드에서 소규모 상태 모델을 작성하는 공통 실습 언어

## 대상 독자

Python을 사용해 본 경험은 필요하지 않습니다. 변수, 조건문, 반복문, 함수 같은 기본 프로그래밍 개념도 1부에서 필요한 만큼 설명합니다. 다만 터미널에서 현재 디렉터리를 확인하고 UTF-8 텍스트 파일을 편집할 수 있어야 합니다.

이 가이드를 시작하기 전에 C나 Java를 배울 필요는 없습니다.

## 선행 개념

- 터미널에서 현재 디렉터리를 확인할 수 있어야 합니다.
- UTF-8 텍스트 파일을 만들고 편집할 수 있어야 합니다.
- 변수·조건문·반복문·함수는 1부에서 다루므로 다른 프로그래밍 언어 경험은 요구하지 않습니다.

## 지원 환경

- Python 3.12 이상
- UTF-8 텍스트 환경
- 문서 학습과 실습 1~6단계: Python 3.12를 실행할 수 있는 환경
- 이 저장소의 공식 `prepare`·`workspace/`·`make`·`verify` 흐름: macOS 또는 Linux
- 프로세스 그룹과 논블로킹 파일 디스크립터를 사용하는 7~8단계 최종 구현: macOS 또는 Linux
- Windows 네이티브 실행 흐름과 프로세스 트리 종료: 지원 범위 밖
- 제3자 Python 패키지: 사용하지 않음

저장소 전체 준비와 검증은 루트 디렉터리에서 실행합니다.

```sh
./prepare.sh
./verify.sh
```

## 완료 후 할 수 있는 일

모든 필수 과정을 마치면 다음 작업을 수행할 수 있어야 합니다.

- 스크립트 실행과 모듈 실행을 구분하고 적절한 진입점을 구성한다.
- Python의 이름·객체·가변성과 주요 컬렉션의 비용 특성을 설명한다.
- 함수의 입력·출력 규칙, 예외 처리 위치, 타입 힌트의 역할을 구분한다.
- 반복자·생성기·컨텍스트 관리자로 데이터 처리 흐름과 자원 수명을 표현한다.
- `pathlib`, JSON, CSV, 임시 파일을 사용해 안전한 CLI 프로그램을 만든다.
- 인자 경계를 보존한 채 외부 명령을 실행하고 종료 상태·표준 출력·표준 오류를 검사한다.
- 제한 시간, 출력 상한, 취소, 자식 프로세스 정리 절차를 설계한다.
- 단위·통합·종단 간 테스트를 분리하고 항상 재현되는 실패 사례를 만든다.
- 작은 Python 프로젝트의 모듈 구조, 타입 정보, 설정, 검증 진입점을 구성한다.

## 학습 방법

`workspace/`는 처음 한 번만 만들고 각 단계에서 다음 순서를 반복합니다.

```text
처음 한 번 `skeleton/`을 `workspace/`로 복사한다
→ 현재 단계와 연결된 문서를 읽는다
→ 현재 단계의 책임만 구현한다
→ 현재 단계까지의 누적 검사를 실행한다
→ 실패 원인을 설명한 뒤 수정한다
→ 1~7단계는 성공한 검사 결과를 학습 기록으로 남긴다
→ 8단계 전체 검사를 통과한 뒤 `reference/` 구현과 비교한다
```

작업 공간은 다음 명령으로 생성합니다.

```sh
scripts/new-workspace.sh exercises/command-checker
```

기존 `workspace/` 디렉터리는 자동으로 덮어쓰지 않습니다.

## 자동 검증의 한계

- 자동 검증은 macOS·Linux에서 POSIX 프로세스 그룹을 사용하는 참고 구현과 명시적 동기화 신호를 사용하는 재현 가능한 `fixture`를 확인합니다.
- 운영체제마다 다른 스케줄러 동작, Windows 네이티브 프로세스 트리, 임의의 외부 실행 파일 동작까지 검증하지는 않습니다.
- 참고 구현이 검사를 통과한다는 사실은 학습자의 설계 설명과 단계별 실패 분석을 대신하지 않습니다.
