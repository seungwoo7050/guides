# 공통 기반을 고르는 방법

모든 개발자가 `c`, `cpp`, `java`, `python`, 웹, 운영체제와 네트워크를 전부 같은 깊이로 배울 필요는 없다. 공통 기반은 **업무 중 다른 계층과 협업하고 실패를 좁힐 수 있는 최소 폭**을 만드는 데 사용한다.

## 모든 트랙의 공통

### `git`

모든 변경은 검토·공유·복구 가능한 형태로 남아야 한다. 다른 브랜치의 코드와 문서를 시작하기 전에 `git`의 작업 트리, 커밋, 원격 브랜치와 복구 절차를 사용할 수 있어야 한다.

## 구현 언어는 하나부터 시작한다

| 목표 | 첫 선택 |
|---|---|
| 프로그래밍 자체와 시스템 기초 | `c` |
| 현대 C++ 애플리케이션·시스템 | `cpp` |
| JVM 백엔드 | `java` |
| 자동화·데이터·AI | `python` |
| 브라우저와 풀스택 웹 | `web-app` 내부 JavaScript·TypeScript |

언어 브랜치 네 개를 모두 완료할 필요는 없다. 첫 분야에서 독립적으로 구현 가능한 언어 하나를 깊게 익힌 뒤, 실제 업무가 요구할 때 두 번째 언어를 추가한다.

## 문제 해결 기반

### `algorithms`

다음 상황에서 필요하다.

- 입력 규모와 비용을 비교해야 한다.
- 데이터 구조 선택이 정확성과 성능을 결정한다.
- 분산 시스템, 컴파일러, 그래픽스, ML 내부구조로 이동한다.
- 후보 구현을 단순 기준 계산과 반례로 검증해야 한다.

제품 기능만 시작하는 단계에서는 전 과정을 선행할 필요가 없다. 복잡도·불변식·기준 구현 절을 먼저 사용하고 필요할 때 확장한다.

## 시스템 관찰 기반

### `unix-systems`

프로세스, 파일, 권한, 네트워크 endpoint와 서비스 상태를 운영체제 명령으로 확인해야 하는 모든 개발자에게 유용하다. 백엔드·인프라·보안 트랙에서는 사실상 공통 기반이다.

### `computer-networks`

HTTP 요청을 넘어서 DNS·TCP·TLS·NAT·라우팅과 실패 계층을 구분해야 할 때 필요하다. 웹·분산·인프라·보안 트랙에서 우선순위가 높다.

### `operating-systems`

동시성, 가상 메모리, 파일·페이지 캐시, I/O와 자원 정책을 설명해야 할 때 필요하다. 시스템·DB·분산·임베디드 트랙에서는 필수에 가깝고, 일반 애플리케이션 개발자에게는 선택 심화다.

### `computer-architecture`

메모리 배치, 캐시, 주소 변환, ISA, SIMD와 하드웨어 비용을 이해해야 할 때 필요하다. 성능·컴파일러·그래픽스·임베디드·저수준 보안 트랙에서 중요하다.

## 공통 기반의 적정 깊이

일반 애플리케이션 개발자는 다음 정도면 충분하다.

```text
Git: 독립 사용
Unix·네트워크: 장애 계층을 좁힐 수 있음
알고리즘: 비용과 정확성의 기본 판단
OS·구조: 인접 시스템과 대화하고 문제를 올바르게 전달할 수 있음
```

시스템·DB·분산·인프라·보안 개발자는 OS·네트워크·구조 중 자신의 핵심 계층을 구현과 검증 수준까지 깊게 다뤄야 한다.

## 선택 규칙

- 업무에서 직접 상태를 소유하는 계층은 **구현·검증 수준**까지 배운다.
- 바로 아래 계층은 **장애 진단과 계약 이해 수준**까지 배운다.
- 두 계층 이상 떨어진 영역은 **존재·책임·연결 지점 인지 수준**이면 충분하다.
- 반복적으로 외부 팀에 문제를 잘못 전달한다면 인접 기반이 부족한 것이다.
- 새로운 프레임워크보다 상태·실패·검증 원리가 우선이다.
