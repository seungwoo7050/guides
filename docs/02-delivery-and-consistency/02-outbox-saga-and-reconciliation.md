# Outbox, Saga와 재조정

## 목표

로컬 transaction과 원격 전달 사이의 간격을 Outbox로 닫고, 여러 서비스가 부분 성공한 상태를 Saga와 재조정으로 최종 상태에 수렴시킵니다.

## 문제

한 서비스의 상태를 저장하고 메시지를 발행하는 다음 코드는 이중 쓰기 문제를 만듭니다.

```text
DB commit 성공
→ 프로세스 중단
→ broker publish 미실행
```

순서를 바꾸어도 문제가 사라지지 않습니다.

```text
broker publish 성공
→ DB commit 실패
```

또한 Outbox가 이벤트를 안정적으로 발행해도 구독 서비스의 transaction과 외부 효과까지 원자적으로 만들지는 못합니다. 각 경계에서 중복과 부분 성공을 처리해야 합니다.

## 계약

### Outbox의 보장 범위를 제한합니다

Outbox는 다음 두 기록을 **같은 로컬 데이터베이스 transaction**에 둡니다.

- 서비스가 소유한 업무 상태 변경
- 발행할 이벤트의 영속 기록

commit되면 둘 다 존재하고 rollback되면 둘 다 없습니다. 발행기는 아직 발행되지 않은 Outbox를 읽어 브로커에 보냅니다.

발행 직후 `published` 표시 전에 중단될 수 있으므로 같은 이벤트가 다시 발행될 수 있습니다. 따라서 다음이 필요합니다.

- 안정적인 `event_id`
- 소비자의 멱등 처리
- 재시도 횟수와 마지막 오류
- 가장 오래된 미발행 이벤트의 나이
- 발행 lease 또는 행 잠금
- 영구 실패를 분리하는 정책

Outbox는 서비스 간 정확히 한 번 transaction을 제공하지 않습니다.

### Saga는 상태 전이와 보상 조건입니다

Saga를 “실패하면 반대 API를 호출하는 패턴”으로만 보면 위험합니다. 각 단계에 다음을 정의해야 합니다.

```text
명령
성공 상태
거절 상태
알 수 없는 상태
보상 가능 조건
보상 명령의 멱등성 키
재시도 종료 조건
```

실제 변경이 적용되었는지 모르는 상태에서 무조건 보상하면 변경이 없던 대상에 반대 효과를 만들 수 있습니다. 먼저 연산 상태를 조회하거나 같은 키로 원래 명령을 다시 확인해야 합니다.

보상보다 전진 복구가 단순한 경우도 있습니다. 예를 들어 읽기 모델 갱신이 실패했다면 원본 상태를 되돌리기보다 이벤트를 다시 발행해 projection을 따라잡게 하는 편이 자연스럽습니다.

### 중간 상태를 숨기지 않습니다

분산 흐름에는 다음과 같은 상태가 필요합니다.

```text
PENDING
ACCEPTED
REJECTED
COMPENSATING
COMPLETED
RECONCILIATION_REQUIRED
```

상태 수를 줄이려고 모든 중간 상태를 예외나 로그에만 남기면 재시작 뒤 무엇을 해야 할지 알 수 없습니다. 각 상태에는 다음을 연결합니다.

- 다음으로 허용되는 전이
- 소유한 서비스
- 만료 또는 재검사 시점
- 관련 operation ID
- 마지막 확인 근거

### 재조정은 정상 운영 경로입니다

재조정 작업은 오래 남은 중간 상태를 찾아 정본과 비교하고, 처음 사용한 키로 다시 진행하거나 운영자에게 넘깁니다.

재조정 작업 자체도 중복 실행될 수 있으므로 다음을 지킵니다.

- 여러 인스턴스가 같은 건을 동시에 처리하지 않도록 lease를 사용합니다.
- lease가 만료되어 다른 인스턴스가 이어받아도 operation ID는 바꾸지 않습니다.
- 비교한 정본과 결정 근거를 기록합니다.
- 성공·거절·수동 확인 필요 상태를 구분합니다.
- 처리 건수뿐 아니라 가장 오래된 대기 시간과 불일치 건수를 지표로 남깁니다.

## 실패 조건

- 업무 상태와 Outbox를 다른 transaction에 저장합니다.
- 발행 전에 Outbox를 완료로 표시합니다.
- publish 성공 뒤 표시 실패에 따른 중복 발행을 고려하지 않습니다.
- 보상 명령에 새 키를 만들어 중복 보상을 허용합니다.
- `PENDING`에 만료와 재조정 주체가 없습니다.
- 재조정 작업이 원본 operation ID 대신 새 요청을 만듭니다.
- Outbox 대기 행 수만 보고 가장 오래된 지연을 측정하지 않습니다.

## 검증

다음 경로를 각각 재현합니다.

1. 업무 상태와 Outbox가 함께 commit됩니다.
2. broker가 중단되면 Outbox가 대기 상태로 남습니다.
3. publish 뒤 표시 전에 중단되면 같은 이벤트가 다시 전달됩니다.
4. 소비자는 중복 이벤트에도 효과를 한 번만 적용합니다.
5. broker 복구 뒤 재조정이 모든 대기 이벤트를 발행합니다.
6. 최종 업무 상태와 읽기 모델이 같은 결과에 수렴합니다.

## 완료 조건

- Outbox가 보장하는 로컬 원자성과 보장하지 않는 원격 범위를 설명할 수 있습니다.
- Saga 단계별 결과·보상·알 수 없음 상태를 정의할 수 있습니다.
- 오래된 중간 상태의 재조정 주체와 종료 조건을 설계합니다.
- publish 뒤 중단에 따른 중복 전달을 검사합니다.
