# 문제 계약과 반례

## 학습 목표

- 자연어 문제를 검증 가능한 계약으로 바꾼다.
- 입력 제한을 알고리즘 선택의 근거로 사용한다.
- 단순하지만 독립적인 기준 풀이를 만든다.
- 코드 분기와 가정을 겨냥한 최소 반례를 설계한다.

## 선행 개념

함수의 매개변수와 반환값, 조건문, 작은 입력을 손으로 추적하는 방법을 알고 있어야 한다.

## 핵심 모델

알고리즘 문제는 “정답을 떠올리는 문제”가 아니라 다음 네 항목을 확정하는 작업이다.

```text
계약: 어떤 입력에 어떤 결과를 내야 하는가?
기준: 가장 단순하게 정확성을 확인하는 방법은 무엇인가?
비용: 입력이 커질 때 어떤 자원이 먼저 부족해지는가?
증거: 구현이 계약을 지켰다는 것을 무엇으로 확인하는가?
```

## 1. 문제를 계약으로 줄이기

구현 전에 다음 표를 채운다.

```text
입력 도메인:
출력 도메인:
성공 조건:
답이 여러 개일 때의 선택 규칙:
답이 없을 때의 결과:
잘못된 입력을 누가 거부하는가:
입력 크기와 값의 범위:
허용 시간과 메모리:
```

예를 들어 “목표 합을 만드는 두 원소를 찾는다”는 설명만으로는 함수가 하나로 정해지지 않는다.

- 같은 위치를 두 번 사용할 수 있는가?
- 같은 값이 여러 번 있으면 어느 인덱스를 반환하는가?
- 해가 여러 개면 사전순 최소 쌍인가, 처음 발견한 쌍인가?
- 해가 없으면 빈 값, 오류, 특수 숫자 중 무엇을 반환하는가?
- 합 계산이 정수 범위를 넘을 수 있는가?

계약이 다르면 올바른 알고리즘과 테스트도 달라진다.

## 2. 입력 제한을 비용 목표로 바꾸기

다음 표는 절대 규칙이 아니라 첫 후보를 고르는 신호다.

| 입력 규모 | 먼저 검토할 비용 |
|---:|---|
| `n <= 20` | 부분집합·순열·백트래킹 |
| `n <= 2,000` | `O(n²)` |
| `n <= 200,000` | `O(n log n)` 또는 `O(n)` |
| 큰 희소 그래프 | `O(V+E)` 또는 `O((V+E) log V)` |

반복문의 개수만 세지 않는다. 다음 숨은 비용을 포함한다.

- 루프 안의 정렬·복사·문자열 슬라이스
- 동적 배열 앞쪽 삭제
- 비교 함수 자체의 비용
- 해시 키 계산 비용
- 재귀 호출 깊이
- 출력 자체의 크기

## 3. 기준 풀이를 먼저 만든다

기준 풀이는 느려도 된다. 대신 후보 구현과 다른 구조를 사용해야 한다.

예시:

| 후보 구현 | 독립 기준 계산 |
|---|---|
| prefix sum | 요청마다 직접 합산 |
| 이분 탐색 | 선형 탐색 |
| Dijkstra | 작은 그래프의 Floyd–Warshall |
| 그리디 구간 선택 | 모든 부분집합 열거 |
| KMP | 단순 위치별 비교 또는 표준 문자열 검색 |
| 최대 유량 | 작은 그래프의 모든 컷 열거 |

후보와 기준이 같은 보조 함수나 같은 전처리를 공유하면 같은 결함을 함께 가질 수 있다.

## 4. 반례는 가정을 겨냥한다

무작위 입력만 늘리기 전에 알고리즘의 가정을 목록으로 만든다.

```text
입력이 비어 있지 않다.
값이 모두 다르다.
가중치가 음수가 아니다.
그래프가 연결되어 있다.
답이 하나뿐이다.
합이 정수 범위를 넘지 않는다.
재귀 깊이가 작다.
```

각 가정을 하나씩 깨는 입력을 만든다.

### 경계 범주

- 빈 입력과 최소 크기
- 같은 값 반복
- 이미 정렬됨과 역순
- 답이 첫 위치·마지막 위치에 있음
- 답이 없음
- 여러 최적해와 동점
- 연결되지 않은 그래프
- 자기 루프와 중복 간선
- 0, 음수, 매우 큰 값
- 긴 공통 접두사나 반복 문자열

## 5. 최소 실패 입력으로 줄이기

실패 입력이 크면 원인보다 증상이 많이 섞인다. 다음 변환을 반복하되 실패가 유지되는지 확인한다.

1. 원소·정점·간선을 절반 제거한다.
2. 값의 절댓값을 줄인다.
3. 중복되지 않은 원소를 제거한다.
4. 문자열의 앞·뒤를 줄인다.
5. 실패와 무관한 연산을 삭제한다.

이 과정은 delta debugging의 단순한 형태다. 최종 반례는 “어떤 가정이 깨졌는지”가 눈에 보여야 한다.

## 6. 재현 가능한 무작위 검사

무작위 검사는 다음 계약을 지킨다.

- 시드를 고정한다.
- 작은 입력부터 시작한다.
- 실패 입력과 시드를 출력한다.
- 기준 풀이와 후보 풀이의 입력을 동일하게 복제한다.
- 실패한 입력을 고정 regression 사례로 추가한다.

무작위 입력은 증명이 아니다. 사람이 예상하지 못한 반례를 찾는 탐색 도구다.

## 완료 기준

- 빈 입력·답 없음·잘못된 입력을 서로 다른 결과로 표현한다.
- 후보와 핵심 로직을 공유하지 않는 작은 기준 풀이를 적는다.
- 특정 가정 하나를 겨냥한 최소 반례와 고정 재현 절차를 남긴다.

## 실패 조건

다음 상태라면 구현을 시작하기 이르다.

- 답이 없을 때의 결과를 설명하지 못한다.
- 입력 제한에서 단순 풀이가 왜 부족한지 계산하지 못한다.
- 후보 구현과 기준 구현이 같은 핵심 로직을 공유한다.
- 샘플 외의 실패 입력을 하나도 제시하지 못한다.
- 무작위 검사에 시드와 실패 입력 보존이 없다.
