# 편집·컴파일·실행: 첫 번째 개발 주기

프로그램을 작성하기 전에 C 언어 전체를 암기할 필요는 없습니다. 다만 소스 파일을 작성하고 실행 파일로 만든 뒤, 실행 결과와 종료 상태를 확인하는 기본 개발 주기는 스스로 수행할 수 있어야 합니다.

## 이 문서를 마치면

- 소스 파일과 실행 파일의 차이를 설명할 수 있습니다.
- 컴파일 오류와 프로그램 실행 결과를 구분할 수 있습니다.
- 표준 출력과 표준 오류, 종료 상태를 확인할 수 있습니다.
- 변경 범위를 작게 유지하며 개발 주기를 반복할 수 있습니다.

## 작업 디렉터리 만들기

```sh
mkdir first-c
cd first-c
pwd
```

`pwd`는 현재 작업 디렉터리를 출력합니다. 이후 명령을 실행할 때는 어떤 파일을 읽고 결과를 어디에 만드는지 현재 작업 디렉터리를 기준으로 확인해야 합니다.

`hello.c` 파일을 만듭니다.

```c
#include <stdio.h>

int main(void)
{
    puts("hello, C");
    return 0;
}
```

다음 명령으로 컴파일합니다.

```sh
cc -std=c99 -Wall -Wextra -Wpedantic hello.c -o hello
```

이 명령은 `hello.c`를 입력으로 받아 `hello`라는 실행 파일을 만듭니다. 컴파일이 정상적으로 끝나면 일반적으로 아무 메시지도 출력하지 않습니다.

실행 파일을 실행하고 종료 상태를 확인합니다.

```sh
./hello
printf 'exit=%s\n' "$?"
```

현재 디렉터리에 있는 실행 파일을 실행할 때는 파일 이름 앞에 `./`를 붙입니다.

이 프로그램에서 종료 상태 `0`은 정상적으로 실행을 마쳤다는 뜻입니다.

## 소스 파일과 실행 파일은 다릅니다

소스 코드를 수정해도 기존 실행 파일은 자동으로 바뀌지 않습니다. 수정 내용을 반영하려면 다시 컴파일해야 합니다.

```text
hello.c 수정
→ cc로 다시 컴파일
→ 새로운 hello 생성
→ ./hello 실행
```

C를 처음 사용할 때 흔히 겪는 문제 중 하나가 "코드를 수정했는데 실행 결과가 바뀌지 않는다"는 상황입니다.

이때는 다음 항목을 먼저 확인합니다.

- 파일을 실제로 저장했는가?
- 올바른 디렉터리에서 작업하고 있는가?
- 소스를 수정한 뒤 다시 컴파일했는가?
- 방금 생성한 실행 파일을 실행하고 있는가?

## 첫 컴파일 오류 읽기

세미콜론 하나를 지운 뒤 다시 컴파일해 봅니다.

```c
puts("hello, C")
```

컴파일러의 오류 메시지는 일반적으로 다음 정보를 포함합니다.

```text
파일 경로 : 줄 : 열 : 오류 종류 : 설명
```

다만 컴파일러가 표시한 위치에 실제 원인이 있다고 단정할 수는 없습니다. 해당 위치는 컴파일러가 코드를 더 이상 정상적으로 해석하지 못한 지점일 수 있습니다.

따라서 오류가 표시된 줄뿐 아니라 그 앞의 코드도 함께 확인해야 합니다.

오류가 여러 개 나타나더라도 한꺼번에 모두 해결하려 하지 않습니다. 가장 먼저 나타난 의미 있는 오류부터 수정한 뒤 다시 컴파일합니다. 하나의 문법 오류 때문에 이후 오류 메시지가 연쇄적으로 발생하는 경우가 많기 때문입니다.

## 표준 출력, 표준 오류, 종료 상태

프로그램의 외부 동작은 화면에 표시되는 출력만으로 정의되지 않습니다.

다음 프로그램을 살펴봅니다.

```c
#include <stdio.h>

int main(int argc, char *argv[])
{
    if (argc != 2)
    {
        fprintf(stderr, "사용법: %s <이름>\n", argv[0]);
        return 2;
    }

    printf("안녕하세요, %s\n", argv[1]);
    return 0;
}
```

컴파일한 뒤 정상 입력과 잘못된 입력을 각각 실행해 봅니다.

```sh
cc -std=c99 -Wall -Wextra -Wpedantic hello.c -o hello

./hello Ada

./hello
printf 'exit=%s\n' "$?"
```

프로그램은 다음 세 가지 방식으로 실행 결과를 외부에 전달합니다.

- `stdout`에는 정상적인 실행 결과를 출력합니다.
- `stderr`에는 오류 메시지나 사용법과 같은 진단 정보를 출력합니다.
- 종료 상태를 통해 셸이나 다른 프로그램이 성공과 실패를 구분할 수 있습니다.

표준 출력과 표준 오류는 리다이렉션으로 분리해 확인할 수 있습니다.

```sh
./hello >out.txt 2>err.txt

cat out.txt
cat err.txt
```

이 구분은 이후 프로그램을 테스트하거나 셸 스크립트와 연동할 때 중요합니다.

## 관찰 가능한 예상 결과를 먼저 적기

코드를 작성하기 전에 입력과 예상 결과를 간단한 표로 정리합니다.

| 입력 | stdout | stderr | 종료 상태 |
| --- | --- | --- | ---: |
| `Ada` | 인사 한 줄 | 없음 | 0 |
| 인자 없음 | 없음 | 사용법 | 2 |
| 인자 두 개 | 없음 | 사용법 | 2 |

이 표는 가장 단순한 형태의 테스트 명세입니다.

"대체로 제대로 동작한다"는 인상이 아니라 외부에서 실제로 관찰할 수 있는 결과를 기준으로 프로그램의 동작을 정의해야 합니다.

예상 결과를 먼저 적어 두면 구현이 바뀌더라도 정상 동작을 판단할 기준이 남습니다.

## 한 번에 한 가지씩 변경하기

처음에는 다음 개발 주기를 짧게 반복합니다.

1. 구현할 동작 하나를 정합니다.
2. 그 동작에 필요한 최소한의 코드를 작성합니다.
3. 경고 옵션을 활성화한 상태로 컴파일합니다.
4. 정상 입력과 실패 입력을 모두 실행합니다.
5. 예상 결과와 실제 결과의 차이를 하나씩 수정합니다.

처음부터 많은 코드를 한꺼번에 작성하면 문법 오류, 입력 처리 문제, 상태 관리 문제, 설계 문제가 동시에 섞이기 쉽습니다.

변경 범위를 작게 유지하면 새로 발생한 문제가 어느 수정에서 비롯되었는지 추적하기 쉽고, 오류의 원인도 더 빠르게 좁힐 수 있습니다.
