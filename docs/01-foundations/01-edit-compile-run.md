# 편집·컴파일·실행: 첫 번째 개발 순환

프로그램을 시작하기 전에 언어 전체를 암기할 필요는 없습니다. 다만 소스 파일을 만들고, 실행 파일로 바꾸고, 결과와 종료 상태를 관찰하는 최소 순환은 스스로 수행할 수 있어야 합니다.

## 이 문서를 마치면

- 소스 파일과 실행 파일을 구분합니다.
- 컴파일 오류와 실행 결과를 구분합니다.
- 표준 출력, 표준 오류와 종료 상태를 관찰합니다.
- 한 번에 한 가지 변경만 하고 결과를 비교합니다.

## 작업 디렉터리 만들기

```sh
mkdir first-c
cd first-c
pwd
```

`pwd`는 현재 디렉터리를 보여 줍니다. 이후 명령이 어느 파일을 읽고 만드는지 항상 현재 위치와 함께 생각합니다.

`hello.c`를 만듭니다.

```c
#include <stdio.h>

int main(void)
{
    puts("hello, C");
    return 0;
}
```

컴파일합니다.

```sh
cc -std=c99 -Wall -Wextra -Wpedantic hello.c -o hello
```

이 명령의 입력은 `hello.c`, 결과는 `hello` 실행 파일입니다. 성공하면 보통 아무 메시지도 출력하지 않습니다.

```sh
./hello
printf 'exit=%s\n' "$?"
```

현재 디렉터리의 실행 파일을 실행하려면 `./`를 사용합니다. 종료 상태 0은 이 프로그램이 약속한 성공입니다.

## 소스와 실행 파일은 다릅니다

소스를 수정한 뒤 다시 컴파일하지 않으면 이전 실행 파일이 계속 실행됩니다.

```text
hello.c를 수정
→ cc를 다시 실행
→ 새 hello 생성
→ ./hello 실행
```

초보 단계에서 자주 생기는 혼란은 “코드를 바꿨는데 결과가 그대로다”입니다. 먼저 저장했는지, 올바른 디렉터리인지, 다시 컴파일했는지 확인합니다.

## 첫 컴파일 오류 읽기

세미콜론 하나를 지우고 다시 컴파일해 봅니다.

```c
puts("hello, C")
```

컴파일러 메시지는 대체로 다음 정보를 포함합니다.

```text
파일 경로 : 줄 : 열 : 오류 종류 : 설명
```

표시된 위치가 항상 원인의 정확한 위치는 아닙니다. 파서가 더 이상 해석할 수 없게 된 지점일 수 있으므로 바로 앞 문장도 확인합니다.

오류를 한꺼번에 많이 만들지 않습니다. 첫 번째 의미 있는 오류부터 고치고 다시 컴파일합니다. 앞 오류 때문에 뒤 메시지가 연쇄적으로 생길 수 있습니다.

## stdout, stderr, 종료 상태

프로그램의 외부 계약은 화면에 보이는 한 줄보다 큽니다.

```c
#include <stdio.h>

int main(int argc, char *argv[])
{
    if (argc != 2)
    {
        fprintf(stderr, "사용법: %s <이름>\n", argv[0]);
        return 2;
    }
    printf("안녕하세요, %s\n", argv[1]);
    return 0;
}
```

```sh
cc -std=c99 -Wall -Wextra -Wpedantic hello.c -o hello
./hello Ada
./hello
printf 'exit=%s\n' "$?"
```

- `stdout`에는 정상 결과를 씁니다.
- `stderr`에는 사용법과 진단을 씁니다.
- 종료 상태는 자동화가 성공과 실패를 구분하게 합니다.

리다이렉션으로 분리해 확인합니다.

```sh
./hello >out.txt 2>err.txt
cat out.txt
cat err.txt
```

## 관찰 가능한 예상값을 먼저 적기

코드를 작성하기 전에 입력과 예상 결과를 작은 표로 적습니다.

| 입력 | stdout | stderr | 종료 상태 |
|---|---|---|---:|
| `Ada` | 인사 한 줄 | 없음 | 0 |
| 인자 없음 | 없음 | 사용법 | 2 |
| 인자 두 개 | 없음 | 사용법 | 2 |

이 표는 가장 작은 테스트 명세가 됩니다. 구현의 느낌이 아니라 외부에서 확인할 수 있는 계약을 제공합니다.

## 한 번에 한 가지 변경

다음 순환을 짧게 유지합니다.

1. 기대 동작 하나를 적습니다.
2. 가장 작은 코드를 작성합니다.
3. 경고를 켜고 컴파일합니다.
4. 성공·실패 입력을 모두 실행합니다.
5. 기대와 실제 차이를 한 가지씩 수정합니다.

큰 코드를 한 번에 작성하면 문법, 입력, 상태와 설계 오류가 섞입니다. 작은 순환은 오류 원인을 좁힙니다.
