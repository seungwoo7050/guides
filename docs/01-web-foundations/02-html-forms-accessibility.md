# HTML 폼과 접근성

HTML 요소는 화면 모양만 만드는 태그가 아닙니다. 링크, 버튼, 입력 필드, 제목, 랜드마크에는 브라우저·키보드·스크린 리더가 공통으로 이해하는 의미와 동작이 있습니다. 용도에 맞는 요소를 사용하면 JavaScript로 다시 구현할 기능이 줄고, 자동 검사도 실제 사용자 동작에 더 가깝게 작성할 수 있습니다.

## 목표

- 문서 랜드마크와 제목 계층을 구성합니다.
- 링크, 버튼, 입력 요소를 목적에 맞게 선택합니다.
- 레이블과 폼 제출의 기본 동작을 활용합니다.
- 키보드 포커스와 비동기 상태를 전달합니다.
- 접근성을 부가 기능이 아닌 기능 요구사항으로 다룹니다.

## 문서의 기본 구조

최소한의 HTML 문서는 다음과 같이 구성할 수 있습니다.

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>내 작업</title>
</head>
<body>
  <header>
    <nav aria-label="주 메뉴">
      <a aria-current="page" href="/">작업</a>
    </nav>
  </header>
  <main id="main">
    <h1>내 작업</h1>
  </main>
</body>
</html>
```

`lang`은 문서 언어를 지정하고, `title`은 브라우저 탭과 방문 기록에 표시할 이름을 제공합니다. `main`은 페이지의 핵심 본문을, `nav`는 주요 탐색 링크 묶음을 나타냅니다. 모든 영역에 ARIA 역할을 추가할 필요는 없습니다. 먼저 HTML 요소가 기본으로 제공하는 의미를 사용합니다.

## 제목 요소는 글자 크기가 아니라 문서 구조를 나타냅니다

페이지의 대표 제목에는 일반적으로 `h1`을 사용하고, 주요 섹션에는 `h2`, 그 하위 주제에는 `h3`을 사용합니다.

```html
<h1>보드 설정</h1>
<section>
  <h2>구성원</h2>
  <article>
    <h3>Kim</h3>
  </article>
</section>
```

글자를 크게 표시하기 위해 제목 단계를 선택해서는 안 됩니다. 시각적 크기는 CSS로 지정합니다. 제목 단계를 임의로 건너뛰면 보조 기술 사용자가 문서 구조를 빠르게 파악하기 어렵습니다.

## 이동에는 링크, 동작에는 버튼을 사용합니다

```html
<a href="/boards/42">보드 열기</a>
<button type="button">메모 추가</button>
```

링크는 다른 주소로 이동할 때 사용하며, 새 탭에서 열기나 주소 복사 같은 브라우저 기능을 기본으로 제공합니다. 버튼은 현재 화면에서 작업을 실행하거나 상태를 바꿀 때 사용합니다. 클릭 이벤트를 붙인 `div`를 버튼처럼 사용하면 Enter·Space 키 동작, 포커스, 비활성화 상태, 접근 가능한 역할을 모두 직접 구현해야 합니다.

폼 안의 버튼은 기본 타입이 `submit`일 수 있습니다. 폼 제출용이 아니라면 `type="button"`을 명시합니다.

## 레이블은 입력 요소의 이름을 제공합니다

플레이스홀더는 입력 예시일 뿐 레이블을 대신하지 못합니다.

```html
<form id="task-form">
  <label for="task-title">새 작업</label>
  <input id="task-title" name="title" autocomplete="off" />
  <button type="submit">추가</button>
</form>
```

`for`와 `id`를 연결하면 레이블을 클릭해 입력 요소에 포커스를 옮길 수 있고, 스크린 리더도 입력 요소의 이름을 읽을 수 있습니다. 입력 오류에 별도 설명을 제공할 때는 `aria-describedby`로 입력 요소와 설명을 연결할 수 있습니다.

```html
<input id="email" aria-describedby="email-error" />
<p id="email-error">이메일 형식을 확인해 주세요.</p>
```

## 폼의 `submit` 이벤트를 기본 경로로 사용합니다

버튼의 `click` 이벤트만 처리하지 말고 폼의 `submit` 이벤트를 처리합니다.

```js
const form = document.querySelector("#task-form");
form.addEventListener("submit", (event) => {
  event.preventDefault();
  // 입력 검증과 저장
});
```

이 방식은 버튼 클릭뿐 아니라 입력 필드에서 Enter를 눌러 제출하는 동작도 처리합니다. 브라우저의 기본 동작을 활용하면 마우스와 키보드의 실행 경로가 불필요하게 분리되지 않습니다.

## 포커스는 사용자의 현재 위치를 보여 줍니다

대체 표시 없이 포커스 윤곽선을 제거해서는 안 됩니다.

```css
:focus-visible {
  outline: 3px solid #f59e0b;
  outline-offset: 3px;
}
```

페이지 맨 앞에는 반복되는 탐색 영역을 건너뛰는 링크를 둘 수 있습니다.

```html
<a class="skip-link" href="#main">본문으로 건너뛰기</a>
<main id="main" tabindex="-1">...</main>
```

모달을 열 때는 포커스를 모달 안의 적절한 요소로 옮기고, 닫을 때는 모달을 열었던 컨트롤로 되돌려야 합니다. 단순히 `z-index`를 높여 화면 위에 표시하는 것만으로는 키보드 탐색을 올바르게 처리할 수 없습니다.

## 비동기 상태와 오류를 알립니다

화면에 새 텍스트가 나타나더라도 보조 기술이 변경 내용을 자동으로 알리지 않을 수 있습니다.

```html
<p role="status" aria-live="polite">저장 중입니다.</p>
<p role="alert">저장하지 못했습니다.</p>
```

`status`는 일반적인 진행 상태에, `alert`는 즉시 알려야 하는 오류에 사용합니다. 모든 텍스트에 라이브 영역을 지정하면 불필요한 알림이 반복될 수 있습니다.

성공·오류·역할을 색만으로 구분해서는 안 됩니다. 텍스트, 아이콘의 접근 가능한 이름, 상태 속성을 함께 제공합니다.

## 접근 가능한 이름으로 검사합니다

사용자 관점의 브라우저 테스트는 CSS 클래스보다 역할과 접근 가능한 이름을 기준으로 요소를 찾습니다.

```ts
page.getByRole("button", { name: "메모 추가" });
page.getByLabel("새 작업");
page.getByRole("alert");
```

클래스 이름이 바뀌어도 사용자에게 보이는 동작과 의미가 같다면 테스트는 유지됩니다. 반대로 레이블이나 버튼 이름이 사라지면 실제 접근성 회귀로 판단해 실패합니다.

## 흔한 오류

- 링크와 버튼을 의미가 아니라 모양만 보고 선택합니다.
- 플레이스홀더를 레이블 대신 사용합니다.
- 버튼의 `click` 이벤트만 처리해 Enter 키 제출이 동작하지 않습니다.
- 다른 포커스 표시를 제공하지 않고 윤곽선을 제거합니다.
- 화면에서 버튼을 숨긴 것으로 서버의 권한 검사를 대신하려 합니다.
- 기본 HTML 요소 대신 불필요한 ARIA를 사용하거나 실제 의미와 다른 역할을 지정합니다.

## 완료 기준

- 문서의 `header`, `nav`, `main`과 제목 계층을 구성할 수 있습니다.

- 레이블이 연결된 폼을 Enter 키로 제출할 수 있습니다.
- 포커스와 비동기 오류를 시각 사용자와 비시각 사용자 모두에게 전달할 수 있습니다.
- 실제 브라우저 테스트가 역할과 이름으로 핵심 컨트롤을 찾습니다.
