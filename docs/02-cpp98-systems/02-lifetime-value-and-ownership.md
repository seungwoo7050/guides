# 객체 수명·값 의미론·소유권

## 주소보다 객체 수명을 먼저 확인합니다

C++에서 수명이 끝난 객체에 접근하거나 같은 자원을 두 번 정리하면 심각한 오류가 발생합니다. 복사 생성과 복사 대입을 구분하지 못하면 정상 경로에서는 동작하지만 예외나 자기 대입에서 상태가 깨지는 타입을 만들기 쉽습니다. 저장 공간을 확보하는 시점부터 객체가 소멸할 때까지 상태를 추적하며 소유자와 실패 후 보장을 확인합니다.

## 저장 공간과 객체 수명의 관계

```text
저장 공간 확보 → 생성 완료 → 유효한 객체 수명 → 소멸 → 저장 공간 반환
                         ├→ 복사: 원본과 독립된 값인가
                         └→ 소유: 누가 자원을 정리하는가

자원 수명 = 객체 수명 → RAII
```

주소 값이 남아 있는 것과 그 위치에 유효한 객체가 살아 있는 것은 서로 다른 문제입니다.

## 1. 저장 공간과 객체 수명은 다릅니다

주소가 존재한다고 해서 그 위치에 유효한 객체가 존재하는 것은 아닙니다.

```text
저장 공간 확보
→ 생성 완료
→ 객체 수명 시작
→ 소멸
→ 저장 공간 반환 또는 재사용
```

- 자동 저장 기간 객체는 선언이 실행되는 시점에 생성됩니다.
- 정상 흐름이나 예외로 범위를 벗어나면 생성의 역순으로 소멸합니다.
- `new T`는 저장 공간을 확보한 뒤 그 공간에 `T`를 생성합니다.
- `delete`는 소멸자를 호출한 뒤 저장 공간을 반환합니다.
- `new` 이후 생성자가 예외를 던지면 해당 `new` 표현식이 확보한 저장 공간은 자동으로 반환됩니다.

파괴된 객체의 이전 주소가 숫자로 남아 있어도 그 주소를 통해 객체를 사용해서는 안 됩니다.

## 2. 생성과 소멸 순서

가장 파생된 객체를 생성할 때 하위 객체는 다음 순서로 초기화됩니다.

1. 가상 기반 클래스
2. 직접 기반 클래스
3. 멤버 선언 순서
4. 생성자 본문

소멸은 반대 순서로 진행됩니다. 초기화 리스트에 적은 순서를 바꿔도 멤버의 실제 초기화 순서는 클래스에 선언된 순서로 결정됩니다.

```cpp
class Session
{
public:
    Session(const std::string &name)
        : name_(name), count_(0)
    {}

private:
    std::string name_; // 먼저 생성
    int count_;        // 다음 생성
};
```

한 멤버의 초기화가 다른 멤버에 의존한다면 선언 순서 자체가 그 의존 관계와 일치해야 합니다.

## 3. 생성자에서 예외가 발생하는 경우

가장 바깥 객체의 생성자가 완료되기 전에 예외가 발생하면 그 객체 자체의 소멸자는 호출되지 않습니다. 대신 이미 생성이 끝난 기반 클래스와 멤버는 역순으로 소멸합니다.

```text
멤버 A 생성 성공
멤버 B 생성 중 실패
→ A 소멸
→ 가장 바깥 객체의 소멸자는 호출되지 않음
```

따라서 생성자 본문에서 여러 원시 자원을 순서대로 직접 획득하기보다, 각 자원을 RAII를 지키는 멤버 객체에 맡기는 편이 안전합니다.

## 4. `new`와 `delete`

```cpp
Widget *one = new Widget;
delete one;

Widget *many = new Widget[10];
delete[] many;
```

`new[]`로 할당한 배열은 `delete[]`로 해제해야 합니다. 두 형식을 섞으면 동작이 정의되지 않습니다. 저장 공간 할당에 성공한 뒤에도 개별 객체 생성자가 실패할 수 있으며, 여러 원시 포인터를 직접 소유하면 어느 단계까지 생성됐는지 수동으로 추적해야 합니다.

동적 할당은 객체가 크다는 이유만으로 선택하는 기본 수단이 아닙니다. 수명이 현재 범위를 넘어야 하거나 동적 다형성이 필요한 경우처럼 분명한 이유가 있어야 합니다. 원소 개수가 실행 중 결정되는 경우에도 원시 배열보다 `std::vector` 같은 표준 컨테이너를 먼저 고려합니다.

## 5. 소유와 대여

포인터나 참조 문법만으로는 소유권이 자동으로 드러나지 않습니다.

```cpp
void inspect(const Record &record); // 잠시 빌려 읽음
void mutate(Record &record);        // 잠시 빌려 변경
Record *find(int id);               // 없을 수 있는 비소유 포인터일 수 있음
Record *create();                   // 호출자가 소유권을 받아야 할 수 있음
```

마지막 두 함수는 반환 타입만으로 소유자를 판단할 수 없습니다. 이름, 문서, 객체 구조를 통해 다음 질문에 답해야 합니다.

- 누가 자원을 획득하는가
- 누가 언제 정리하는가
- 빌린 참조나 포인터는 언제까지 유효한가
- 소유권을 다른 객체로 이전할 수 있는가

C++98 표준 라이브러리에는 유일 소유권을 명확히 표현하는 `unique_ptr`가 없으므로, 필요한 경우 복사를 금지한 전용 소유자 클래스를 작성합니다. `std::auto_ptr`는 복사처럼 보이는 연산이 소유권을 이전하는 등 제약이 커서 일반 컨테이너 요소와 현대적인 소유권 모델의 대안으로 사용하지 않습니다.

## 6. RAII

RAII는 자원의 수명을 객체 수명에 결합하는 방식입니다.

```cpp
class File
{
public:
    explicit File(const char *path);
    ~File();

private:
    File(const File &);
    File &operator=(const File &);

    int fd_;
};
```

생성자가 파일을 열고 소멸자가 닫으면 함수가 정상 반환하거나 예외로 끝나는 모든 경로의 정리 책임을 한곳에 모을 수 있습니다.

RAII로 관리할 대상은 메모리에 한정되지 않습니다.

- 파일 디스크립터
- 소켓
- 잠금
- 임시 파일
- 등록 상태
- 변경 후 복원해야 하는 스트림 설정

## 7. 복사 생성자

복사 생성자는 아직 존재하지 않는 새 객체를 기존 객체의 값으로 생성합니다.

```cpp
Buffer copy(original);
```

컴파일러가 생성한 기본 복사 생성자는 각 멤버를 복사합니다. 멤버에 소유 포인터가 있다면 주소만 복사되어 두 객체가 같은 메모리를 소유하게 될 수 있습니다.

```cpp
class Buffer
{
public:
    Buffer(const char *text);
    Buffer(const Buffer &other);
    ~Buffer();

private:
    char *data_;
    std::size_t size_;
};
```

값 타입이라면 복사 후 원본과 사본을 독립적으로 변경하고 소멸할 수 있어야 합니다. 원시 버퍼를 직접 소유하는 예제에서는 새 저장 공간을 확보하고 내용을 복사하는 깊은 복사가 필요합니다.

## 8. 복사 대입

복사 대입은 이미 살아 있는 객체의 값을 다른 객체의 값으로 교체합니다.

```cpp
second = first;
```

대상 객체가 기존 자원을 소유하므로 복사 생성보다 고려할 사항이 많습니다.

- 새 값 준비가 실패할 수 있습니다.
- 기존 자원을 먼저 버리면 실패 시 이전 값까지 잃습니다.
- `value = value`에서는 원본과 대상이 같으므로 읽을 데이터를 먼저 지울 수 있습니다.

따라서 기존 자원 해제 후 새 자원 할당 순서로 단순 구현하면 예외 안전성과 자기 대입에서 문제가 생기기 쉽습니다.

## 9. Rule of Three와 Canonical Form

직접 자원을 소유하는 타입에서 다음 함수 중 하나를 정의해야 한다면 나머지 함수의 의미도 함께 검토합니다.

1. 복사 생성자
2. 복사 대입 연산자
3. 소멸자

이 원칙을 Rule of Three라고 합니다. 학습 자료에서 말하는 Orthodox Canonical Form은 기본 생성자까지 포함해 클래스의 대표적인 특수 멤버 함수 형태를 나열하는 경우가 많습니다. 두 용어를 같은 의미로 사용하지 않습니다.

모든 클래스가 이 함수들을 직접 구현해야 하는 것은 아닙니다. `std::string`과 `std::vector`처럼 올바른 값 의미론을 제공하는 멤버만 보유한다면 컴파일러가 생성한 연산을 사용하는 편이 더 안전합니다.

복사가 의미 없는 자원 소유자는 C++98에서 복사 연산을 비공개로 선언하고 정의하지 않아 사용을 막습니다.

```cpp
private:
    Socket(const Socket &);
    Socket &operator=(const Socket &);
```

## 10. copy-and-swap

copy-and-swap은 새 값을 대상 객체 밖에서 완성한 뒤 마지막에 교체합니다.

```cpp
Buffer &Buffer::operator=(const Buffer &other)
{
    Buffer candidate(other); // 실패하면 *this는 바뀌지 않음
    swap(candidate);         // 예외를 던지지 않아야 함
    return *this;
}
```

교체가 끝난 뒤 `candidate`는 대상이 이전에 소유하던 자원을 가지며 함수가 끝날 때 이를 정리합니다.

```text
후보 객체 완성
→ 예외를 던지지 않는 swap으로 반영
→ 이전 상태는 후보 객체 소멸자가 정리
```

이 패턴은 자기 대입에도 안전합니다. 다만 임시 복사 비용이 있으므로 모든 대입 연산에 기계적으로 적용할 필요는 없습니다.

## 11. 예외 안전성 보장

| 보장 수준 | 실패 후 상태 |
|---|---|
| 기본 보장 | 자원 누수 없이 유효하고 소멸할 수 있지만 값은 일부 바뀔 수 있습니다. |
| 강한 보장 | 연산이 성공하거나 관찰 가능한 상태가 호출 전과 같습니다. |
| 무예외 보장 | 연산이 예외를 밖으로 내보내지 않습니다. |

소멸자와 `swap`처럼 정리 또는 최종 반영에 사용하는 연산은 예외를 던지지 않도록 설계합니다. 강한 예외 보장은 함수 이름이 아니라 실제 연산 순서로 확인해야 합니다.

```text
기존 상태를 건드리지 않고 후보 준비
→ 실패 가능한 작업을 모두 완료
→ 실패하지 않는 한 단계로 공개 상태에 반영
```

## 12. 값 타입 예제: 고정소수점 수

값을 원시 정수와 고정된 소수 비트 수로 표현하는 타입은 값 의미론을 연습하기 좋습니다.

```cpp
class Fixed
{
public:
    Fixed();
    explicit Fixed(int value);
    explicit Fixed(double value);

    double toDouble() const;
    int raw() const;

    Fixed operator+(const Fixed &other) const;
    bool operator<(const Fixed &other) const;

private:
    int raw_;
    static const int fractionalBits_ = 8;
};
```

설계 전에 다음 사항을 결정합니다.

- 표현 가능한 범위
- 변환 시 반올림 방식
- 오버플로 처리 정책
- 비교를 원시 값 비교로 구현해도 되는가
- `operator+`가 피연산자를 변경하지 않는가

연산자 오버로딩은 타입의 의미를 내장 연산과 자연스럽게 대응시킬 때만 사용합니다. `operator+`가 왼쪽 피연산자를 몰래 변경하거나 비교 결과가 외부 상태에 의존하면 사용자가 기대하는 값 연산의 의미를 깨뜨립니다.

## 13. Modern C++에서 달라지는 표현

원칙은 같지만 의도를 더 직접적으로 표현할 수 있습니다.

| 의도 | C++98 | Modern C++ |
|---|---|---|
| 복사 금지 | 비공개 선언 후 미정의 | `= delete` |
| 유일 소유 | 전용 소유자 직접 작성 | `std::unique_ptr` |
| 소유권 이전 | 별도 `release`·`swap` 규칙 | 이동 생성자·이동 대입 |
| 기본 연산 명시 | 선언을 생략해 암묵 생성 | `= default` |
| 원시 자원 직접 소유 최소화 | Rule of Three | Rule of Zero |

핵심은 동일합니다. **어떤 자원을 누가 언제까지 소유하는지 타입과 객체 구조에 드러내야 합니다.**

## 14. 다형적 객체 복사 예고

기반 클래스 포인터가 가리키는 실제 파생 타입을 보존하지 않고 기반 타입 값으로 복사하면 객체 슬라이싱이 발생합니다. 파생 클래스가 자기 실제 타입을 복사하는 `clone()`을 제공할 수 있지만, 반환된 포인터의 소유자와 여러 객체를 복사하다 실패했을 때의 정리 방식도 함께 설계해야 합니다. 자세한 내용은 다형성 문서에서 다룹니다.

## 작은 실습: `TextBuffer`

다음 불변식을 가진 동적 문자열 타입을 작성합니다.

```text
- data_는 유효한 null 종료 문자열을 가리키거나 명시적으로 정의한 빈 상태입니다.
- size_는 문자열 길이와 일치합니다.
- 복사한 두 객체는 서로 독립적입니다.
```

필요한 공개 함수:

```cpp
class TextBuffer
{
public:
    TextBuffer();
    explicit TextBuffer(const char *text);
    TextBuffer(const TextBuffer &other);
    ~TextBuffer();
    TextBuffer &operator=(const TextBuffer &other);

    const char *c_str() const;
    std::size_t size() const;
    void swap(TextBuffer &other) throw();

private:
    char *data_;
    std::size_t size_;
};
```

빈 상태에서도 `c_str()`이 null을 반환할지 빈 문자열을 반환할지 공개 규칙을 하나로 정하고 모든 연산에서 유지합니다.

### 단계별 진행

1. 완성된 생성자와 소멸자의 동작을 확인합니다.
2. 복사 생성자 본문을 보지 않고 작성합니다.
3. 테스트만 보고 복사 대입 연산자를 작성합니다.
4. 복사 대입을 copy-and-swap으로 다시 구현합니다.
5. `Key`, `Value`, `Request`가 이 타입을 값으로 사용하게 합니다.

### 실패 주입

- 원본과 사본 중 하나를 변경합니다.
- 자기 대입을 수행합니다.
- 빈 문자열과 긴 문자열을 복사합니다.
- 할당 실패를 주입해 강한 예외 보장을 확인합니다.
- 생성·복사·소멸 횟수를 세어 누수와 이중 파괴를 찾습니다.

## 복사·할당에서 자주 발생하는 수명 오류

- 소멸자만 작성하고 복사 연산은 컴파일러 기본 동작에 맡깁니다.
- 대입 연산에서 새 값 준비 전에 기존 자원을 지웁니다.
- 생성자 본문에서 여러 원시 포인터를 획득한 뒤 중간 실패를 처리하지 않습니다.
- 빌린 참조를 소유자보다 오래 보관합니다.
- `delete`와 `delete[]`를 혼동합니다.
- Modern C++ 코드에서 이동 후 객체의 이전 값이 유지된다고 가정합니다.

## 다른 언어와 비교

Java와 C#은 메모리 회수를 GC가 담당하지만 파일, 소켓, 잠금 같은 외부 자원의 수명은 여전히 명시적으로 관리해야 합니다. `try-with-resources`, `using`, `finally`는 문법은 다르지만 정리 시점을 보장하려는 같은 문제를 해결합니다. 값 객체의 불변식, 복사 독립성, 소유와 대여의 경계도 언어와 관계없이 유지됩니다.

## 수명과 예외 안전성 점검

- 객체 생성 중 실패했을 때 가장 바깥 객체의 소멸자가 호출되지 않는 이유는 무엇입니까?
- 복사 생성자와 복사 대입 연산자의 실패 경로는 어떻게 다릅니까?
- 소유 포인터를 가진 타입에서 기본 복사가 위험한 이유는 무엇입니까?
- copy-and-swap에서 공개 상태가 실제로 바뀌는 지점은 어디입니까?
- 강한 예외 보장을 연산 순서로 설명할 수 있습니까?
- 포인터 값이 존재해도 대상 객체를 사용할 수 없는 경우를 세 가지 설명할 수 있습니까?
