# 선형 구조, 구간과 해시

## 학습 목표

- 배열·연결 구조·stack·queue·deque를 필요한 연산으로 구분한다.
- 반열린 구간과 prefix sum으로 경계 오류를 줄인다.
- 단조 stack·queue가 각 원소를 제한된 횟수만 처리하는 이유를 설명한다.
- 해시의 기대 비용, 충돌과 키 계약을 구분한다.

## 선행 개념

배열·리스트의 인덱스, [점근 분석](../01-foundations/02-asymptotic-analysis.md)과 입력 계약을 먼저 이해해야 한다.

## 핵심 모델

자료구조 선택은 “익숙한 컨테이너”가 아니라 필요한 연산의 집합에서 시작한다.

```text
무엇을 자주 읽는가?
어디에 삽입·삭제하는가?
순서를 유지해야 하는가?
최솟값·최댓값·최근 값 중 무엇이 필요한가?
키로 찾는가, 위치로 찾는가?
```

## 1. 선형 구조의 연산 계약

| 구조 | 강한 연산 | 주의할 연산 |
|---|---|---|
| 동적 배열 | 임의 위치 읽기, 뒤 append | 중간 삽입·삭제, 재할당 |
| 연결 구조 | 노드를 알고 있을 때 삽입·삭제 | 임의 위치 접근, cache locality |
| stack | 최근 원소 push/pop | 중간 원소 접근 |
| queue | 먼저 들어온 원소 처리 | 뒤에서 제거 |
| deque | 양 끝 삽입·삭제 | 일반 임의 중간 삽입 |

동적 배열 append는 한 번의 연산이 아니라 연산열 전체에서 상각 `O(1)`인 경우가 많다. 재할당 시 기존 원소 이동과 참조 무효화를 고려한다.

## 2. 반열린 구간

구간 `[left, right)`는 다음 장점이 있다.

- 길이는 `right-left`다.
- 빈 구간은 `left==right`다.
- 인접 구간 `[a,b)`와 `[b,c)`가 겹치지 않는다.
- 배열 전체는 `[0,n)`으로 표현된다.

구간 합 API도 같은 계약을 사용한다.

```text
prefix[0] = 0
prefix[i+1] = prefix[i] + A[i]
sum(left, right) = prefix[right] - prefix[left]
```

전처리 `O(n)`, 각 질의 `O(1)`, 추가 공간 `O(n)`이다.

### 경계 불변식

```text
prefix의 길이는 n+1이다.
0 <= left <= right <= n이다.
prefix[i]는 A[0:i]의 합이다.
```

## 3. 차분 배열

여러 구간에 같은 값을 더한 뒤 최종 배열만 필요하다면 차분을 사용한다.

```text
diff[left] += value
diff[right] -= value
```

마지막에 prefix를 한 번 계산해 실제 값을 복원한다. 중간 상태에서 개별 값 질의가 필요하거나 업데이트와 질의가 섞이면 Fenwick tree나 segment tree 같은 다른 구조가 필요하다.

## 4. 두 포인터와 sliding window

두 포인터가 안전하려면 포인터를 이동해도 버린 후보가 다시 필요하지 않다는 단조성이 있어야 한다.

예를 들어 모든 값이 음수가 아닌 배열에서 합이 상한을 넘으면 왼쪽을 이동해 합을 줄일 수 있다. 음수가 섞이면 오른쪽을 늘렸을 때 합이 단조 증가하지 않으므로 같은 논리가 깨진다.

```text
상태: [left, right)와 현재 구간 정보
불변식: 저장된 정보는 정확히 현재 구간을 나타낸다.
진행: right를 늘리고, 위반 조건이 사라질 때까지 left를 늘린다.
```

## 5. 단조 stack과 deque

다음 큰 원소, 구간 최댓값 같은 문제에서는 후보를 단조 순서로 유지한다.

- 새 값보다 약한 뒤쪽 후보는 앞으로도 답이 될 수 없으면 제거한다.
- 만료된 인덱스는 앞에서 제거한다.
- 각 원소는 최대 한 번 들어가고 한 번 나오므로 전체 `O(n)`이다.

중첩 `while`이 있어도 총 pop 횟수로 분석해야 한다.

## 6. 해시 구조

해시 table은 키를 bucket으로 보내고 충돌을 처리한다.

### 계약

- 같은 키는 같은 hash를 가져야 한다.
- 동등성 규칙과 hash 규칙이 일치해야 한다.
- mutable 값을 key로 사용하면 삽입 뒤 위치를 찾지 못할 수 있다.
- 조회·삽입은 보통 기대 `O(1)`이며 최악 보장은 다를 수 있다.

### 자주 쓰는 상태

- 등장 여부: set
- 빈도: key → count
- 마지막 위치: key → index
- prefix 상태의 첫 위치: cumulative value → earliest index

## 7. 예제: 합이 `k`인 가장 긴 부분 배열

음수가 허용되면 sliding window는 안전하지 않다. prefix sum `S[i]`와 과거의 `S[j]=S[i]-k`를 찾는다.

```text
상태: 각 prefix 값이 처음 나타난 위치
불변식: i를 처리하기 전 map에는 prefix[0:i]의 최초 위치가 있다.
```

최초 위치만 보존해야 길이가 최대가 된다. 같은 prefix가 다시 나왔을 때 덮어쓰면 더 긴 답을 잃는다.

- 구간 길이와 마지막 인덱스를 섞는다.

- 해시 연산을 무조건 최악 `O(1)`로 표현한다.
- mutable key나 서로 다른 동등성·hash 규칙을 사용한다.
