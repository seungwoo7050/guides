# 파일, 경로와 메타데이터

경로는 파일 자체가 아니라 **이름을 따라 객체를 찾는 방법**입니다. 같은 파일 시스템 객체가 여러 경로로 보일 수 있고, 경로가 사라져도 이미 열린 객체는 남을 수 있습니다. 파일을 변경하기 전에 경로 구성 요소, 링크, 메타데이터와 마운트 경계를 확인해야 합니다.

## 학습 목표

- 절대 경로, 상대 경로와 현재 작업 디렉터리의 관계를 설명합니다.
- 경로명, 디렉터리 항목과 파일 시스템 객체를 구분합니다.
- 심볼릭 링크와 하드 링크의 수명 차이를 설명합니다.
- 파일 유형·소유자·모드·크기·시간·링크 수를 관찰합니다.
- 경로 삭제와 열린 파일 수명이 다를 수 있음을 설명합니다.
- 변경 전에 대상 경로와 파일 시스템 경계를 확인합니다.

## 선행 개념

- user space/kernel 파일 접근과 절대·상대 경로 구분

## 경로 해석 모델

```text
경로 문자열
  │ 절대 경로면 /, 상대 경로면 현재 작업 디렉터리에서 시작
  ▼
구성 요소별 디렉터리 탐색
  │ 이름 → 다음 객체
  ▼
최종 디렉터리 항목
  │
  ▼
파일 시스템 객체의 메타데이터
  ├─ 유형
  ├─ 소유자와 그룹
  ├─ 권한·ACL
  ├─ 크기와 타임스탬프
  └─ 링크 수
```

경로 해석 중 하나의 부모 디렉터리를 통과하지 못하면 최종 파일 모드가 허용되어 보여도 접근할 수 없습니다.

## 절대 경로와 상대 경로

절대 경로는 루트 `/`에서 시작합니다.

```text
/tmp/report.log
/Users/developer/project
/home/developer/project
```

상대 경로는 현재 작업 디렉터리에서 시작합니다.

```text
config/app.json
../shared/data
./run
```

특수 표기:

| 표기 | 의미 |
|---|---|
| `.` | 현재 디렉터리 |
| `..` | 부모 디렉터리 |
| `/` | 루트 디렉터리 |
| `~` | 셸이 확장하는 홈 디렉터리 표기 |

`~`는 파일 시스템의 특별한 경로 요소가 아니라 셸 확장입니다. 작은따옴표 안에서는 일반적으로 확장되지 않습니다.

```sh
printf '%s\n' ~
printf '%s\n' '~'
```

서비스나 테스트가 상대 경로를 사용한다면 실행 주체가 어떤 작업 디렉터리에서 시작하는지 계약으로 정해야 합니다.

## 경로명과 객체

디렉터리는 이름을 객체에 연결합니다. 이름 변경은 파일 데이터 자체를 다시 쓰는 동작과 다릅니다.

```text
디렉터리 A
  report.txt ──► 객체 123

디렉터리 B
  latest.txt ──► 객체 123  (하드 링크 가능)
```

파일을 삭제한다는 말은 보통 디렉터리 항목 하나를 제거한다는 뜻입니다. 다른 하드 링크나 열린 파일 참조가 남아 있으면 객체와 데이터는 즉시 사라지지 않을 수 있습니다.

## 파일 유형 관찰

이름의 확장자만으로 유형을 단정하지 않습니다.

```sh
ls -ld -- path 2>/dev/null || ls -ld path
file path
```

`file`은 내용과 메타데이터를 바탕으로 유형을 추정할 뿐 신뢰성이나 안전성을 보증하지 않습니다.

플랫폼별 `stat` 사용법은 다릅니다.

```sh
# GNU/Linux
stat -c '%n %F %A %U:%G %s %h' path

# macOS
stat -f '%N %HT %Sp %Su:%Sg %z %l' path
```

확인할 항목:

- regular file, directory, symbolic link, socket, FIFO 등 유형
- 소유자와 그룹
- 모드와 ACL
- 크기
- 수정·상태 변경 시간
- 링크 수
- 가능하면 객체 식별자와 파일 시스템

## 심볼릭 링크

심볼릭 링크는 다른 경로 문자열을 저장하는 별도 객체입니다.

```sh
ln -s releases/v2 current
ls -l current
readlink current
```

링크 자체가 존재해도 저장된 대상 경로가 사라지면 끊어진 링크가 됩니다.

```text
current exists as a symlink
current's target does not exist
```

다음을 구분합니다.

```sh
# 링크 자체의 존재와 정보
ls -ld current
readlink current

# 링크를 따라간 최종 대상
ls -ld current/
```

상대 심볼릭 링크의 대상은 링크가 놓인 디렉터리를 기준으로 해석됩니다. 현재 셸 디렉터리를 기준으로 단정하면 안 됩니다.

배포에서 `current` 링크를 바꿀 때는 새 대상이 완전한지 검증한 뒤 이름 교체를 원자적으로 수행하는 방식을 고려합니다. 중간에 존재하지 않는 대상을 가리키는 순간을 만들지 않는 것이 목적입니다.

## 하드 링크와 링크 수

하드 링크는 같은 파일 시스템 객체를 다른 디렉터리 항목이 가리키게 합니다.

```sh
ln original.txt second-name.txt
```

일반적으로 디렉터리나 다른 파일 시스템을 가로지르는 하드 링크는 제한됩니다. 링크 수가 0이 되고 열린 참조도 없어질 때 객체의 저장 공간이 회수될 수 있습니다.

## 삭제됐지만 열린 파일

프로세스가 파일을 연 뒤 경로가 삭제될 수 있습니다.

```text
경로명 제거
≠
열린 파일 디스크립터 즉시 종료
```

프로세스는 이미 열린 객체에 계속 쓸 수 있으며, 데이터가 커져도 경로 목록에서는 보이지 않을 수 있습니다. 로그 파일을 삭제했는데 디스크 공간이 줄지 않는 대표 원인입니다.

Linux에서는 `/proc/PID/fd`나 `lsof`, macOS에서는 `lsof`로 확인할 수 있습니다.

```sh
lsof -p PID
```

해결은 무조건 프로세스를 강제 종료하는 것이 아닙니다. 애플리케이션이 로그를 다시 열도록 지원하면 그 계약을 사용하고, 그렇지 않다면 정상 종료·재시작이 데이터와 요청에 미치는 영향을 검토합니다.

## 마운트와 파일 시스템 경계

하나의 `/` 트리 아래에 여러 파일 시스템이 연결될 수 있습니다.

```text
/
├── home 또는 Users
├── tmp
└── 별도 볼륨·네트워크 파일 시스템·컨테이너 마운트
```

같은 경로 트리 안에 있다는 이유로 다음이 같다고 가정하지 않습니다.

- 원자적 rename 보장 범위
- 대소문자 구분
- 최대 파일 이름
- 권한·ACL 의미
- 사용 가능한 공간과 inode
- 내구성·동기화 특성

대상 파일과 임시 파일이 다른 파일 시스템에 있으면 `rename` 기반 원자적 교체가 실패하거나 복사로 바뀔 수 있습니다. 변경 전에 마운트 경계를 확인합니다.

```sh
df -h path
```

Linux에서는 필요하면 다음을 사용합니다.

```sh
findmnt -T path
```

macOS에서는 `mount`, `df`, `diskutil` 중 증상에 필요한 최소 도구만 사용합니다.

## 안전한 관찰 순서

```text
1. pwd로 상대 경로 기준을 확인합니다.
2. 부모 디렉터리부터 구성 요소별로 존재 여부를 확인합니다.
3. 링크 자체와 링크가 가리키는 대상을 분리합니다.
4. 유형·소유자·모드·크기·링크 수를 기록합니다.
5. 대상이 어느 파일 시스템에 있는지 확인합니다.
6. 열린 프로세스 참조가 있는지 확인합니다.
7. 그 뒤에만 생성·이동·삭제를 수행합니다.
```

경로에 공백, 개행, glob 문자나 `-`로 시작하는 이름이 있을 수 있습니다. 관찰 명령에서도 인자 경계를 보존하고 지원되는 경우 `--`를 사용합니다.
