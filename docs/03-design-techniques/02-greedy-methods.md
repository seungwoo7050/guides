# 그리디 설계

## 학습 목표

- 그리디 선택을 명시적인 순서와 상태 갱신으로 표현한다.
- 교환 논리 또는 구조적 성질로 최적성을 증명한다.
- 그리디가 실패하는 최소 반례를 만든다.
- tie-break가 정확성과 재현성에 미치는 영향을 설명한다.

## 선행 개념

최적해의 계약, 최소 반례와 [정확성 설명](../01-foundations/04-correctness-and-invariants.md)을 작성할 수 있어야 한다.

## 핵심 모델

그리디 알고리즘은 각 단계에서 하나의 선택을 확정하고 되돌리지 않는다.

```text
선택 규칙 + 선택 뒤 남는 문제 + 안전성 증명
```

국소적으로 좋아 보인다는 사실만으로는 충분하지 않다.

## 1. 설계 절차

1. 가장 단순한 최적화 계약을 쓴다.
2. 후보를 어떤 순서로 볼지 정한다.
3. 현재 선택이 미래 선택에 주는 제약을 쓴다.
4. 이 선택을 포함하는 최적해가 항상 존재함을 증명한다.
5. 선택 뒤 남은 문제가 같은 형태인지 확인한다.

## 2. 예제: 최대 구간 선택

서로 겹치지 않는 구간을 가장 많이 선택한다. 각 구간은 반열린 `[start,end)`이고 `start < end`다.

선택 규칙: 끝 시간이 가장 이른 구간부터 고른다.

```text
sort intervals by (end, start)
last_end = -infinity
for interval in order:
    if interval.start >= last_end:
        choose interval
        last_end = interval.end
```

### 교환 논리

임의의 최적해에서 첫 구간을 `o`라 하고 그리디 첫 구간을 `g`라 하자. `g.end <= o.end`다. `o`를 `g`로 바꿔도 이후 구간이 시작할 수 있는 시간은 늦어지지 않는다. 따라서 `g`를 포함하는 최적해가 존재한다. 남은 구간에도 같은 논리를 적용한다.

시작 시간이 가장 빠른 구간을 고르는 규칙은 긴 구간 하나가 많은 짧은 구간을 막는 반례에서 실패한다.

## 3. 안전한 선택과 남은 문제

선택 뒤 상태가 단순해야 한다.

구간 선택에서는 `last_end` 하나만 남는다. 이미 고른 구간의 전체 목록은 다음 선택 가능성을 판단하는 데 필요하지 않다. 이처럼 과거 정보를 버릴 수 있는 이유를 설명해야 한다.

## 4. MST의 그리디

Kruskal과 Prim은 단순히 가장 싼 간선을 고르는 알고리즘이 아니다.

- Kruskal: 서로 다른 component를 연결하는 간선 중 전역 최소를 선택
- Prim: 현재 tree와 바깥을 가르는 절단의 최소 간선을 선택

둘 다 절단 성질로 안전성을 설명한다. cycle을 만드는 싼 간선은 선택하지 않는다.

## 5. Huffman coding

빈도가 가장 낮은 두 symbol tree를 합치는 선택을 반복한다. optimal prefix code에서 가장 낮은 두 빈도를 sibling leaf로 둘 수 있다는 교환 구조가 핵심이다. 단순히 “작은 것부터 합치면 합이 작다”만으로는 충분하지 않다.

## 6. 그리디가 실패하는 신호

- 현재 선택이 미래 가능한 선택을 복잡하게 바꾼다.
- 한 선택의 손해를 이후 선택이 보상할 수 있다.
- 최적해 사이의 교환이 실행 가능성을 보존하지 않는다.
- 같은 상태에 도달하는 여러 과거 경로의 가치가 다르다.
- 작은 반례에서 다른 첫 선택이 더 좋다.

0/1 knapsack에서 가치/무게 비율이 큰 물건부터 고르는 규칙은 fractional knapsack과 달리 일반적으로 최적이 아니다.

## 7. tie-break

동점 규칙은 다음을 위해 필요하다.

- 결과의 결정성
- 테스트 재현성
- 후속 상태의 안전성
- lexicographic 최소 같은 추가 계약

동점이 최적값에는 영향이 없어도 반환하는 해의 모양에는 영향을 준다. API 계약에 포함한다.

[설계 기법 exercise](../../exercises/03-design-techniques/README.md)에서 종료 시간 우선 구간 선택을 모든 부분집합 optimum과 대조하고, 시작 시간 우선 fixture의 최소 반례를 보존한다.

## 완료 기준

- 국소 선택이 실행 가능성을 보존하는 조건을 명시한다.
- 임의 최적해를 선택을 포함하는 최적해로 바꾸는 교환 단계를 적는다.
- 같은 최적값에서 결과를 결정하는 tie-break를 구현과 문서에 일치시킨다.

## 실패 조건

- 샘플에서 맞는다는 이유로 그리디를 채택한다.
- 교환 후 실행 가능성이 유지되는지 보이지 않는다.
- “가장 작은 값”이 어떤 후보 집합에서의 최소인지 불명확하다.
- cycle·capacity 같은 제약을 선택 규칙에서 빠뜨린다.
- tie-break가 구현마다 달라진다.
