# React 폼과 목록

폼과 목록에서는 상태, 식별자, 접근성, 서버 오류가 한꺼번에 만납니다. 입력값을 React state로 제어할지 브라우저에 맡길지, 제출과 검증을 어느 계층에서 처리할지, 항목의 식별자를 어떻게 유지할지 결정해야 합니다.

## 목표

- 제어 컴포넌트와 비제어 컴포넌트를 목적에 맞게 선택합니다.
- 폼 제출과 브라우저의 기본 동작을 유지합니다.
- 클라이언트 검증과 서버 검증의 역할을 구분합니다.
- 목록의 `key`, 빈 상태, 오류, 낙관적 항목을 처리합니다.
- 포커스와 오류 연결을 사용자 관점에서 검증합니다.

## 제어 입력

```tsx
const [title, setTitle] = useState("");

<input
  id="title"
  value={title}
  onChange={(event) => setTitle(event.target.value)}
/>
```

React state가 현재 입력값의 기준이 됩니다. 입력값을 다른 UI에 즉시 반영하거나 글자 수와 조건부 컨트롤을 표시할 때 유용합니다. 키 입력마다 다시 렌더링되므로, 지나치게 큰 컴포넌트 트리가 입력 상태를 소유하지 않게 합니다.

## 비제어 입력

간단한 폼은 제출할 때 `FormData`로 값을 읽을 수 있습니다.

```tsx
function submit(event: FormEvent<HTMLFormElement>) {
  event.preventDefault();
  const data = new FormData(event.currentTarget);
  const title = String(data.get("title") ?? "").trim();
}
```

파일 입력처럼 브라우저가 값의 생명주기를 관리하는 컨트롤에도 적합합니다. 제어 방식과 비제어 방식 중 하나가 항상 더 나은 것은 아닙니다. 입력값이 필요한 시점과 이를 읽는 범위를 기준으로 선택합니다.

## 폼 제출

```tsx
<form onSubmit={handleSubmit}>
  <label htmlFor="title">보드 제목</label>
  <input id="title" name="title" />
  <button type="submit">만들기</button>
</form>
```

버튼의 `onClick`만 처리하지 않습니다. 폼의 `submit` 이벤트를 사용하면 Enter 키 제출과 브라우저가 제공하는 폼 의미를 유지할 수 있습니다. 제출 중에는 중복 제출을 막고 진행 상태를 별도로 알립니다. `disabled` 요소는 포커스를 받을 수 없으므로 사용자가 상태 설명을 확인할 수 있는지도 고려해야 합니다.

## 클라이언트 검증과 서버 검증

클라이언트 검증은 사용자에게 빠른 피드백을 제공합니다.

```tsx
const normalized = title.trim();
if (!normalized) setError("제목을 입력해 주세요.");
```

서버는 같은 규칙을 다시 검사해야 합니다. 사용자는 클라이언트 코드를 우회할 수 있고 클라이언트와 서버의 배포 버전이 다를 수도 있습니다. 중복 여부, 권한, 현재 버전처럼 서버 상태가 필요한 규칙은 클라이언트만으로 판정할 수 없습니다.

## 오류를 입력 필드와 연결합니다

```tsx
<label htmlFor="title">보드 제목</label>
<input
  id="title"
  aria-invalid={Boolean(error)}
  aria-describedby={error ? "title-error" : undefined}
/>
{error ? <p id="title-error">{error}</p> : null}
```

제출에 실패하면 첫 번째 오류 필드로 포커스를 옮길 수 있습니다. 다만 사용자가 입력하는 매 순간 포커스를 강제로 이동해서는 안 됩니다. 서버가 반환하는 일관된 오류 코드를 사용자에게 보여 줄 문장으로 변환합니다.

## 목록 상태

다음 상태를 구분합니다.

```tsx
if (state.status === "loading") return <p role="status">불러오는 중</p>;
if (state.status === "error") return <p role="alert">{state.message}</p>;
if (state.items.length === 0) return <p>아직 보드가 없습니다.</p>;
```

불러오는 중인 상태와 정상적으로 불러왔지만 결과가 없는 상태는 다릅니다. 기존 목록을 유지한 채 백그라운드에서 새로고침한다면 그 상태도 별도로 표현합니다.

## `key`와 항목 내부 상태

안정적인 ID를 `key`로 사용합니다.

```tsx
{boards.map((board) => <BoardCard key={board.id} board={board} />)}
```

배열 인덱스를 사용하면 정렬 후 다른 카드에 메뉴 열림 상태나 입력 초안이 연결될 수 있습니다. 서버 ID가 아직 없는 낙관적 항목에는 클라이언트에서 생성한 안정적인 임시 ID를 사용합니다.

## 낙관적 업데이트

사용자에게 빠르게 반응하기 위해 서버 응답을 기다리기 전에 목록을 변경할 수 있습니다.

```text
현재 목록 보존
→ 임시 항목 추가
→ 요청 전송
→ 성공하면 서버 결과로 교체
→ 실패하면 해당 변경을 되돌리거나 실패 상태로 표시
```

실패했을 때 과거 배열 전체로 되돌리면 그사이에 성공한 다른 변경까지 사라질 수 있습니다. 작업 ID나 항목별 상태를 사용해 실패한 변경만 복구합니다. 서버 충돌은 단순한 네트워크 오류와 다르므로 최신 서버 상태를 다시 받아 조정해야 할 수 있습니다.

## 삭제와 확인

각 삭제 버튼에는 대상이 드러나는 접근 가능한 이름을 제공합니다.

```tsx
<button aria-label={`${board.title} 삭제`}>삭제</button>
```

확인이 필요한 파괴적 작업에는 모달의 포커스 이동, Escape 키 처리, 닫은 뒤 포커스 복귀까지 설계합니다. 모든 삭제에 확인 창을 강제하면 작업 흐름을 방해할 수 있으므로, 실행 취소가 가능한 경우에는 다른 방식도 검토합니다.

## 흔한 오류

- 폼의 `submit` 대신 버튼의 `click`만 처리합니다.
- 클라이언트 검증을 서버의 보안 검증으로 간주합니다.
- 모든 오류를 폼 위의 한 문장으로만 표시합니다.
- 대기 상태와 빈 결과 상태를 같은 UI로 표현합니다.
- 배열 인덱스를 `key`로 사용합니다.
- 낙관적 업데이트가 실패했을 때 관련 없는 최신 변경까지 되돌립니다.
