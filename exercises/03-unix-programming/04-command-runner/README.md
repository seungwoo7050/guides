# 연습문제: command-runner

## 목표

명령 문자열 하나를 lexer·parser·executor 단계로 나누어 실행합니다. 인용, 빈 인자, 최대 한 개의 파이프, 문법 오류와 프로세스 종료 상태를 검증합니다.

## 구현 위치

`skeleton/command_runner.c`를 구현합니다. 대화형 prompt와 환경 변수 확장은 범위 밖입니다.

## 문법

- 인용되지 않은 공백은 인자를 나눕니다.
- 작은따옴표 안의 문자는 그대로 유지합니다.
- 큰따옴표 안에서는 역슬래시가 다음 문자 하나를 literal로 만듭니다.
- 인용되지 않은 역슬래시도 다음 문자 하나를 literal로 만듭니다.
- 붙어 있는 인용 조각은 하나의 단어입니다.
- `''`와 `""`는 빈 인자를 만듭니다.
- 인용되지 않은 `|` 하나만 지원합니다.
- 인용되지 않은 `<`, `>`, `;`, `&`는 구현되지 않은 제어 연산자이므로 문법 오류입니다. 인용하거나 escape하면 일반 문자로 전달합니다.

## 오류와 상태

- 빈 명령, 빈 파이프 쪽, 두 개 이상의 파이프, 열린 따옴표와 끝의 역슬래시는 문법 오류입니다.
- 전체 입력의 파싱이 성공한 뒤에만 자식을 만듭니다. 문법 오류는 stderr 진단과 상태 2를 반환하며 실행 부수효과를 만들지 않습니다.
- 외부 명령의 상태를 그대로 반환합니다.
- 없는 명령은 127, 실행 불가는 126입니다.
- 시그널 종료는 `128 + signal`로 변환합니다.
- 파이프라인은 마지막 명령 상태를 반환합니다.
- 부모와 자식은 사용하지 않는 파이프 끝을 닫으며, 표준 FD가 닫혀 번호 0·1이 재사용되어도 최종 연결을 보존합니다.

## 완료 기준

- `make exercise-test`와 `make sanitize`가 통과하며 작은·큰따옴표, escape, 붙은 인용 조각과 빈 인자가 기대한 argv 경계를 만듭니다.
- 빈 명령·열린 따옴표·끝 역슬래시·빈 파이프 쪽·복수 파이프·제어 연산자를 상태 2로 거부하고 파싱 실패가 실행 부수효과를 남기지 않습니다.
- 4 MiB 파이프와 표준 FD 재사용 환경이 교착 없이 끝나며 마지막 명령의 일반·126·127·시그널 상태를 반환합니다.

## 자기 설명

- 전체 파싱이 끝난 뒤에만 `fork`해야 문법 오류의 무효과 계약을 보장할 수 있는 이유는 무엇인가요?
- lexer가 따옴표를 제거하면서도 빈 인자와 붙은 인용 조각의 단어 경계를 보존하려면 어떤 상태를 기록해야 하나요?

## 검증

```sh
make exercise-test
make sanitize
```

검사는 실제 argv와 인용된 제어 문자, 4 MiB 파이프, 126·127·시그널 상태, 마지막 명령 상태, 문법 오류의 무효과, 표준 FD 재사용과 timeout을 확인합니다.
