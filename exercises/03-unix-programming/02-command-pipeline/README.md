# 연습문제: command-pipeline

## 목표

두 외부 명령을 파이프로 연결하고 모든 프로세스에서 사용하지 않는 파일 디스크립터를 닫습니다. 큰 입력에서도 교착하지 않고 마지막 명령의 종료 상태를 반환해야 합니다.

## 구현 위치

저장소 루트에서 다음 명령을 실행한 뒤 `workspace/src/command_pipeline.c`를 구현합니다. 공개 헤더는 변경하지 않습니다.

```sh
scripts/new-workspace.sh exercises/03-unix-programming/02-command-pipeline
cd exercises/03-unix-programming/02-command-pipeline
```

기준 구현과 권장 구현 순서는 자신의 검사가 통과한 뒤 [`reference/`](reference/README.md)에서 비교합니다.

## 계약

- 입력 argv 배열과 각 `argv[0]`, `out_status`는 유효해야 합니다.
- 성공적으로 두 자식을 생성·회수하면 0을 반환하고 마지막 명령 상태를 `*out_status`에 씁니다.
- 준비·`fork`·`waitpid` 실패는 -1이며 `out_status`를 변경하지 않습니다.
- `exec`에서 명령을 찾지 못하면 자식 상태 127, 그 밖의 실행 실패는 126입니다.
- 시그널 종료는 `128 + signal`로 변환합니다.
- 왼쪽 명령의 실패는 파이프라인의 공개 상태를 덮지 않습니다. 마지막 명령 상태가 결과입니다.
- 부모와 두 자식은 사용하지 않는 파이프 끝을 모두 닫습니다.
- 표준 FD가 닫힌 환경에서 파이프 끝이 0 또는 1로 재사용되어도 최종 stdin/stdout을 실수로 닫지 않습니다.
- 두 자식을 모두 시작한 뒤 기다립니다. 첫 자식이 파이프 용량보다 많이 쓰더라도 교착하지 않아야 합니다.

## 완료 기준

- `make exercise-test`와 `make sanitize`가 통과하며 4 MiB 이상을 전달하는 파이프라인이 timeout이나 교착 없이 끝납니다.
- 마지막 명령의 일반·126·127·시그널 종료 상태가 공개 결과가 되고, 왼쪽 명령의 실패가 이를 덮지 않음을 확인합니다.
- 반복 실행 전후 열린 FD 수와 표준 FD 0·1을 닫은 환경의 동작을 검사해 부모와 두 자식에 불필요한 파이프 끝이 남지 않음을 증명합니다.

## 자기 설명

- 부모가 첫 자식을 기다리기 전에 두 자식을 모두 시작하고 사용하지 않는 파이프 끝을 닫아야 하는 이유는 무엇인가요?
- `dup2` 대상과 원본 FD 번호가 같을 수 있는 상황에서 무조건 close하면 어떤 표준 스트림을 잃을 수 있나요?

## 검증

```sh
make exercise-test
make sanitize
```

검사는 4 MiB 전송, 마지막 명령 상태, 시그널 종료, 실행 권한 오류, 잘못된 입력, 반복 실행 뒤 FD 누수를 포함합니다.
