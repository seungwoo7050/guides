# 문서 중심 실습

이 디렉터리의 실습은 외부 시스템을 공격하는 절차가 아니라, 보안 업무에서 반복해서 작성하는 **판단 산출물**을 훈련합니다. 각 실습은 작은 합성 시스템과 불완전한 증거를 제공합니다. 학습자는 확인된 사실, 미확인 가설과 추가로 필요한 증거를 분리해 결과물을 작성합니다.

## 공통 반복

```text
초기 자료를 읽습니다.
→ 보호할 상태와 허가 범위를 확인합니다.
→ 사실·가설·미확인을 나눕니다.
→ 필요한 최소 추가 증거를 정합니다.
→ 산출물을 작성합니다.
→ 반례와 잘못된 결론을 검토합니다.
→ rubric으로 자기 검증합니다.
```

## 작업공간

문서 실습은 저장소 루트에서 다음 명령으로 시작합니다. `<id>`에는 실습 디렉터리와 같은 전체 ID(예: `01-scope-and-evidence`)를 넣습니다.

```sh
python3 scripts/new_workspace.py exercise <id>
```

명령은 해당 실습의 미완성 `template/`을 `work/` 디렉터리에 복사합니다. 원본 `inputs/`는 제자리에서 읽고 `template/`와 함께 비교 기준으로 보존합니다. 기존 경로나 심볼릭 링크가 있으면 초기화는 덮어쓰지 않고 실패해야 합니다. 실습 07은 실행형 실습이므로 자체 README의 절차를 따릅니다.

## 안전 범위

- 입력은 저장소 파일과 합성 데이터뿐입니다.
- 외부 주소, 실제 계정, 실제 credential과 실제 사용자 데이터는 사용하지 않습니다.
- 제공 자료만으로 결론을 내릴 수 없으면 `unknown`으로 기록합니다.
- 영향 증명을 위해 데이터를 추가로 획득하거나 제3자를 시험하도록 제안하지 않습니다.
- 공격 이름보다 전제, 상태 변화, 증거, 수정과 탐지를 설명합니다.

## 답안과 자동 검사의 범위

완성 답안은 제공하지 않습니다. 보안 판단에는 시스템 맥락과 위험 수용자가 필요하므로 하나의 문구를 정답으로 고정하면 학습 목표가 훼손됩니다. 각 실습은 대신 다음을 제공합니다.

- 초기 상태와 입력 자료
- 필수 산출물
- 허용·금지 범위
- 대표적인 잘못된 결론
- 완료 rubric

루트 `verify.sh`는 fixture 형식과 링크를 검사하지만 판단의 타당성을 대신 평가하지 않습니다. `CYBERSECURITY_VERIFY_WORK=1 ./verify.sh`를 실행하면 생성된 제출물의 필수 파일·형식도 검사하지만, 보안 주장과 사람의 의사결정이 타당하다고 인증하지는 않습니다. 각 실습의 reviewer 질문과 제출 evidence를 함께 사용해야 합니다. 최종 Capstone은 구조 검사기를 제공해 필수 근거의 누락을 거부합니다.
