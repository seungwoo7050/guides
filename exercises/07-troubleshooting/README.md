# 장애 진단과 복구

## 진단 순서

정상 스택에 작은 설정 오류를 한 개씩 주입하고, 증상에서 실패 계층을 좁힙니다. 이 실습은 새 기능 구현이 아니라 다음 진단 순서를 반복하는 데 목적이 있습니다.

```text
컨테이너 상태
→ 프로세스
→ listen 포트
→ DNS
→ 네트워크 연결
→ 프로토콜 응답
→ 설정과 secret
→ 파일·volume 상태
```

## 시나리오

| 이름 | 주입한 오류 | 예상 핵심 증상 |
|---|---|---|
| `wrong-db-host` | 존재하지 않는 데이터베이스 서비스 이름 | 애플리케이션이 데이터베이스 호스트를 해석하지 못하고 종료 |
| `wrong-db-password` | 애플리케이션에만 잘못된 비밀값 제공 | 데이터베이스는 정상이지만 애플리케이션 인증 실패 |
| `missing-secret` | 존재하지 않는 비밀값 경로 | 애플리케이션이 데이터베이스 접속 전에 즉시 실패 |
| `wrong-fcgi-port` | Nginx 업스트림을 `app:9999`로 변경 | 게이트웨이 자체 상태 검사는 통과하지만 동적 요청은 502 |
| `broken-healthcheck` | 정상 게이트웨이의 검사 명령만 `false`로 변경 | 외부 요청은 성공하지만 컨테이너 상태 검사는 실패 |
| `data-loss` | 이름 있는 볼륨을 명시적으로 삭제 | 무상태 컨테이너 재생성과 달리 저장 데이터 소실 |

## 실행

```sh
cd exercises/07-troubleshooting
./run-scenario.sh wrong-fcgi-port
```

전체 자동 검증:

```sh
./verify.sh
```

각 시나리오가 끝나면 자원을 정리합니다. `data-loss`는 의도적으로 볼륨을 삭제하므로 다른 실습 데이터와 프로젝트 이름을 공유하지 않습니다.
