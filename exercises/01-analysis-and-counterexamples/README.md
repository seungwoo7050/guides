# 01. 분석과 반례

## 목표

코드를 작성하기 전에 문제의 의미와 검증 방법을 고정한다.

## 문제 A — 첫 삽입 위치

정렬된 정수 수열과 target이 주어질 때 첫 `value >= target` 위치를 반환한다.

다음을 작성한다.

1. 빈 수열과 모든 값보다 큰 target의 결과
2. 반열린 탐색 구간의 불변식
3. 선형 기준 풀이
4. 중복 값에서 임의 일치 위치를 반환하는 결함의 최소 반례
5. 시간·추가 공간

## 문제 B — 최대 구간 선택

반열린 구간 중 서로 겹치지 않는 최대 개수의 구간을 고른다.

다음을 작성한다.

1. 잘못된 구간 입력의 처리
2. 시작 시간 우선 규칙이 실패하는 최소 반례
3. 종료 시간 우선 규칙의 교환 논리
4. 모든 부분집합을 사용하는 기준 풀이의 비용
5. 동점 정렬 규칙

## 문제 C — 최단 경로

가중 directed graph에서 한 시작점의 최단 거리를 구한다.

다음을 작성한다.

1. 음수 edge, 음수 cycle, 도달 불가능의 계약
2. Dijkstra 전조건
3. Bellman–Ford의 `k`번째 반복 불변식
4. 작은 graph에서 사용할 독립 기준 계산
5. reachable negative cycle과 unreachable negative cycle을 구분하는 입력

## 제출 rubric

각 문제는 다음 8항목으로 확인한다.

```text
[ ] 입력·출력 계약이 완전하다.
[ ] 답 없음과 잘못된 입력이 구분된다.
[ ] 기준 풀이가 후보와 독립적이다.
[ ] 입력 크기 변수가 정의되어 있다.
[ ] 시간과 공간이 모두 있다.
[ ] 불변식이 검증 가능한 문장이다.
[ ] 종료 근거가 있다.
[ ] 최소 반례가 특정 가정을 깨뜨린다.
```

자동 채점은 하지 않는다. 증명 문장을 형식만 맞춰 통과시키는 것보다 반례와 논리의 타당성을 사람이 검토하는 편이 정확하다.

## 완료 기준

- 세 문제마다 입력·출력·오류·답 없음이 구분된 계약을 제출한다.
- 후보와 다른 계산 방법의 기준 풀이 및 시간·공간 비용을 적는다.
- 결함 가정 하나를 직접 깨는 최소 반례를 문제마다 하나 이상 남긴다.

## 자기 설명

- lower bound의 반열린 구간 불변식이 종료 시 첫 삽입 위치를 가리키는 이유는 무엇인가?
- unreachable 음수 cycle과 reachable 음수 cycle의 결과 계약이 달라야 하는 이유는 무엇인가?

## 검증

짝 검토자는 각 rubric 항목에 근거 문장 또는 반례가 실제로 있는지 확인한다. 저장소 구조와 문서 계약은 루트에서 다음 명령으로 검사한다.

```sh
make docs-check
```
