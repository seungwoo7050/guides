# 네트워크 기능 설계 검토 질문

새 프로토콜, 외부 API, 프록시, 부하 분산기 또는 실시간 연결을 추가할 때 사용하는 질문입니다. 모든 항목을 문서로 길게 작성할 필요는 없지만 답하지 못한 항목을 가정으로 남겨야 합니다.

## 이름과 주소

- 서비스 이름의 소유자와 TTL은 누구인가요?
- A, AAAA와 HTTPS 레코드를 모두 고려하나요?
- 여러 주소 후보의 시도와 대체 순서는 무엇인가요?
- 컨테이너, 호스트, VPN과 클라우드 네임스페이스마다 이름 해석기가 다른가요?
- 출발지 주소와 출력 인터페이스를 고정해야 하나요?

## 경로와 MTU

- 직접 연결, 게이트웨이와 터널 중 어떤 경로를 사용하나요?
- 최장 프리픽스 일치 뒤 적용되는 정책은 무엇인가요?
- 경로의 최소 MTU와 캡슐화 부가 크기는 얼마인가요?
- ICMP와 ICMPv6의 필요한 유형을 허용하나요?
- 패킷 단편화에 의존하나요, 응용 프로그램이 크기를 제한하나요?

## 전송 규칙

- 데이터 모델은 스트림인가요, 데이터그램인가요, 독립 스트림 묶음인가요?
- 메시지 경계 구분과 최대 크기는 무엇인가요?
- 순서, 손실, 중복과 늦은 데이터의 처리 규칙은 무엇인가요?
- 연결 시간 제한, 읽기 시간 제한과 전체 기한을 구분하나요?
- 재시도가 안전한 조건과 멱등 키는 무엇인가요?
- 연결 풀과 임시 포트의 상한은 무엇인가요?

## 흐름과 혼잡

- 생산자가 소비자보다 빠를 때 역압은 어디까지 전달되나요?
- 응용 프로그램 대기열, 소켓 버퍼와 브로커 대기열의 최대 크기는 무엇인가요?
- 재시도 폭주를 막는 지수 백오프, 무작위 지연과 회로 차단기가 있나요?
- 처리량과 함께 RTT, 재전송, 대기열 깊이와 꼬리 지연 시간을 측정하나요?
- UDP 기반 프로토콜이 혼잡 제어를 구현하거나 재사용하나요?

## NAT, 프록시와 방화벽

- 어느 방향에서 새 흐름을 시작할 수 있나요?
- SNAT·DNAT 뒤 원래 클라이언트 식별이 필요한가요?
- 전달 헤더와 PROXY 프로토콜을 어느 홉까지 신뢰하나요?
- NAT 대응 관계, 연결 추적과 유휴 시간 제한은 얼마인가요?
- IPv4와 IPv6 정책이 같은 의도를 구현하나요?
- 장애 조치에서 상태가 복제되거나 연결이 명시적으로 다시 수립되나요?

## TLS와 응용 보안

- 호스트 이름과 인증서 체인을 검증하나요?
- SNI와 ALPN이 올바르게 전달되나요?
- 0-RTT에서 replay 가능한 작업을 제한하나요?
- TLS 종료 지점 뒤의 내부 구간도 보호해야 하나요?
- 네트워크 위치나 출발지 IP를 사용자 인증으로 오해하지 않나요?

## 관측과 장애 복구

- DNS, 연결, TLS와 응용 처리 시간을 분리해 기록하나요?
- 로컬·원격 주소 쌍, 프로토콜 버전과 ALPN을 기록하나요?
- 패킷 수집 없이도 재시도와 시간 초과 원인을 볼 지표가 있나요?
- 패킷 수집이 필요할 때 개인정보와 비밀값을 어떻게 보호하나요?
- 경로 변경, 패킷 손실, MTU 축소와 상대 노드 재시작을 시험했나요?
- 변경 실패 시 되돌리기와 상태 정리 절차가 있나요?

## 검토 결론 형식

```text
보장하는 것:
보장하지 않는 것:
상한과 시간 제한:
실패 시 관찰 가능한 신호:
재시도와 중복 처리:
보안 경계:
검증 명령과 고정 입력:
남은 가정:
```

이 형식은 “TCP를 쓰므로 안전합니다” 또는 “HTTP/3라서 빠릅니다” 같은 프로토콜 이름 중심 결론을 실제 동작 규칙으로 바꿉니다.
