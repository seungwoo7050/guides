# Cloud-computing 계약 증거 지도

이 문서는 `main` SHA `887f4b8a679195c5b6c13457a91e0b0af357ccff`의 `cloud-computing` 계약을 학습 파일에서 역추적하는 색인입니다. `OWN-*`과 `EXIT-*`는 이 브랜치 안에서만 쓰는 안정적인 증거 ID입니다. Capstone의 machine-readable 연결은 [`evidence-manifest.json`](../projects/multitenant-document-processing-saas/reference/evidence-manifest.json), 실제 local 실행 근거는 [`local-model-report.json`](../projects/multitenant-document-processing-saas/reference/evidence/local-model-report.json), 사람 판정은 [`manual-review-guide.md`](manual-review-guide.md)에 고정합니다. 자동 검사는 파일 구조와 공개 불변식의 보조 근거이며 설계 판단의 타당성을 대신하지 않습니다.

추적 순서는 다음과 같습니다.

```text
main 계약 → 개념 설명 → 단계 실습과 대표 실패 → Capstone 누적 산출물 → 종료 근거 → 사람 판정
```

## Capstone 단계와 구현 owner handoff

[`evidence-manifest.json`](../projects/multitenant-document-processing-saas/reference/evidence-manifest.json)은 `iaas → managed-platform → faas → saas` 순서와 각 단계의 아홉 file+heading 근거를 고정합니다. 이 manifest는 다음 인접 구현을 cloud-computing의 소유 범위와 구분합니다.

| 구현 owner branch | 넘기는 계약 | cloud-computing에 남는 판단 |
|---|---|---|
| `web-infra` | 단일 host·container·DNS·TLS·배포·backup 운영 | cloud service로 이동할 때 바뀌는 책임·failure·cost |
| `web-app` | organization membership·authentication·session·API authorization | SaaS tenant context와 공급자·고객 책임 |
| `database-systems` | tenant 관계 schema·constraint·transaction·query isolation | managed database·tenant data 경계의 외부 계약 |
| `distributed-services` | 일반 retry·idempotency·Outbox·Saga·DLQ | FaaS delivery·concurrency·timeout에 그 계약을 적용하는 방법 |
| `cybersecurity` | credential threat·취약점 검증·공격 탐지·incident recovery | cloud identity·tenant isolation의 책임·evidence 요구 |
| `platform-engineering` | 여러 팀의 Kubernetes·IaC module·golden path·self-service tenancy | 한 workload와 작은 SaaS의 cloud service 선택 경계 |

## 판정 규칙

1. `owns`에 연결된 개념만 읽고 실습·대표 실패를 수행하지 않았다면 완료가 아닙니다.
2. 단계 실습의 결과가 Capstone에서 같은 workload·tenant·event·resource ID로 결합되지 않으면 완료가 아닙니다.
3. 자동 검사가 통과해도 책임·비용·복구·공급자 의미의 타당성을 사람이 검토하지 않았다면 교육적 완료로 판정하지 않습니다.
4. 실제 cloud 계정은 필수가 아닙니다. 실행한다면 [cloud experiment safety](cloud-experiment-safety.md)의 최소 권한·예산·중단·cleanup 계약을 먼저 충족해야 합니다.
5. 최종 사람 판정은 [manual review guide](manual-review-guide.md)에 따라 `EXIT-1..4` 각각을 `충족`, `보완 필요`, `범위 밖`으로 기록하며, 남은 조건에는 owner·due·verification·rollback이 필요합니다.
