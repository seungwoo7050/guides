# 용어집

본문에서 자주 쓰는 용어를 빠르게 확인할 수 있도록 정리했습니다. 명령과 설정 이름은 원래 표기를 함께 적었습니다.

## 네트워크와 요청

### 바인드(bind)

서버 소켓을 특정 IP 주소와 포트 또는 Unix 소켓 경로에 연결하는 동작입니다. 서버는 바인드한 뒤 연결을 기다립니다.

### 클라이언트(client)

연결과 요청을 시작하는 프로세스입니다. 브라우저, `curl`, 데이터베이스 클라이언트가 여기에 해당합니다.

### 서버(server)

주소와 포트 또는 소켓에서 요청을 기다리고 응답하는 프로세스입니다.

### 소켓(socket)

프로세스가 통신하는 끝점입니다. TCP 소켓과 Unix 도메인 소켓 등이 있습니다.

### 수신 대기(listen)

서버 소켓이 들어오는 연결을 기다리는 상태입니다.

### 포트(port)

한 IP 주소 안에서 연결 대상을 구분하는 16비트 번호입니다. 서버와 클라이언트의 설정이 일치해야 합니다.

### DNS

이름을 IP 주소 등으로 해석하는 시스템입니다. Docker 사용자 정의 네트워크에서도 서비스 이름을 찾는 데 사용합니다.

### HTTP와 HTTPS

HTTP는 요청과 응답 형식을 정하는 애플리케이션 프로토콜입니다. HTTPS는 HTTP를 TLS 연결 위에서 전달합니다.

### TLS

통신 암호화와 상대 인증을 제공하는 프로토콜입니다.

### FastCGI

웹 서버가 장기 실행 애플리케이션 프로세스에 요청 정보를 전달하는 프로토콜입니다. 이 저장소에서는 Nginx와 PHP-FPM 사이에서 사용합니다.

### 역방향 프록시(reverse proxy)

클라이언트 요청을 먼저 받은 뒤 내부 서비스에 전달하고 응답을 되돌려 주는 서버입니다.

### 게이트웨이(gateway)

외부 요청을 가장 먼저 받는 서비스입니다. TLS 종료와 라우팅, 역방향 프록시를 담당할 수 있습니다.

## 컨테이너와 저장소

### 이미지(image)

컨테이너를 만들 때 사용하는 읽기 전용 파일 시스템 계층과 실행 설정의 묶음입니다.

### 컨테이너(container)

이미지를 바탕으로 실행한 격리된 프로세스와 그 실행 환경입니다.

### 계층(layer)

이미지 파일 시스템의 변경분입니다. Dockerfile의 여러 단계가 누적되어 이미지를 구성합니다.

### 빌드 컨텍스트(build context)

`docker build`가 빌더에 전달하는 파일 집합입니다. Dockerfile의 `COPY`는 이 범위 안의 파일만 읽습니다.

### 쓰기 가능 계층(writable layer)

실행 중인 컨테이너가 이미지 위에 기록하는 변경분입니다. 컨테이너를 삭제하면 함께 사라집니다.

### 볼륨(volume)

컨테이너 파일 계층과 독립적으로 데이터를 저장하는 Docker 마운트 유형입니다.

### 이름 있는 볼륨(named volume)

Docker가 이름과 수명을 관리하는 영속 저장소입니다. 컨테이너를 삭제해도 명시적으로 지우기 전까지 남습니다.

### 호스트 경로 마운트(bind mount)

호스트의 파일이나 디렉터리를 컨테이너 경로에 연결하는 방식입니다. 호스트 경로와 권한에 영향을 받습니다.

### 네트워크 네임스페이스(network namespace)

프로세스가 보는 네트워크 인터페이스, 경로와 소켓을 격리한 관점입니다. 컨테이너마다 별도 관점을 가질 수 있습니다.

## 프로세스와 운영

### 프로세스(process)

프로그램이 실행되어 PID, 메모리, 열린 파일과 환경변수 등의 상태를 가진 인스턴스입니다.

### PID 1

컨테이너 안의 첫 프로세스입니다. Docker가 보내는 시그널을 직접 받고 컨테이너의 수명을 결정합니다.

### 시그널(signal)

운영체제가 프로세스에 보내는 비동기 알림입니다. `SIGTERM`은 정상 종료 요청, `SIGKILL`은 즉시 종료 요청입니다.

### 전경 실행(foreground)

프로세스가 실행을 유지하며 터미널 또는 컨테이너의 주 프로세스로 남는 상태입니다.

### 종료 코드(exit code)

프로세스가 끝나면서 반환하는 정수입니다. 일반적으로 0은 성공, 0이 아닌 값은 실패를 뜻합니다.

### 표준 출력과 표준 오류

프로세스의 일반 출력과 진단 출력을 분리하는 표준 스트림입니다. 컨테이너 로그는 보통 두 스트림을 수집합니다.

### 상태 검사(healthcheck)

컨테이너 안에서 명령을 반복 실행해 서비스 상태를 판정하는 검사입니다. 검사 명령과 종료 코드가 상태의 의미를 결정합니다.

### 생존 검사(liveness)

프로세스가 회복 불가능한 상태인지 판정하는 검사입니다.

### 준비 상태 검사(readiness)

현재 새 요청을 받을 준비가 됐는지 판정하는 검사입니다.

### 기본 동작 검사(smoke test)

배포나 시작 직후 핵심 경로가 동작하는지 외부 관점에서 확인하는 짧은 검사입니다.

## 데이터와 보안

### 멱등성(idempotency)

같은 작업을 여러 번 실행해도 결과가 한 번 실행한 상태와 같아지는 성질입니다.

### 초기화(bootstrap)

빈 상태 또는 이전 상태를 서비스가 실행 가능한 원하는 상태로 바꾸는 과정입니다.

### 스키마 변경(migration)

데이터베이스 스키마나 데이터를 한 버전에서 다음 버전으로 변경하는 절차입니다.

### 비밀값(secret)

비밀번호, 토큰과 개인키처럼 노출되면 안 되는 값입니다. 이미지와 일반 설정에서 분리해 관리합니다.

### 인증 기관(CA)

다른 주체의 인증서에 서명해 신뢰 체인을 만드는 기관입니다.
