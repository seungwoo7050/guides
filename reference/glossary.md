# 운영체제 용어집

이 용어집은 본문에서 같은 단어를 다른 계층의 뜻으로 섞지 않기 위한 빠른 참조입니다. 구현마다 명칭이 다를 수 있으므로 정의보다 더 좁거나 넓은 의미로 쓰는 문서를 만났다면 해당 문서의 계약을 우선 확인하세요.

## 커널 경계와 실행

| 용어 | 이 가이드에서 사용하는 뜻 |
|---|---|
| 커널 | 특권 상태에서 CPU, 메모리와 장치를 관리하는 운영체제 핵심입니다. |
| 사용자 모드 | 애플리케이션이 제한된 권한으로 실행되는 CPU 모드입니다. |
| 커널 모드 | 페이지 테이블, 인터럽트와 장치 같은 특권 자원을 다룰 수 있는 CPU 모드입니다. |
| 시스템 호출 | 사용자 프로그램이 커널 서비스를 의도적으로 요청하는 동기 진입입니다. |
| 트랩 | 문헌에 따라 동기 예외 전체 또는 의도적인 진입을 가리키는 용어이므로 문맥을 확인해야 합니다. |
| 예외 | 현재 명령어 실행에서 동기적으로 발생한 제어 이전입니다. |
| 폴트 | 커널 처리 뒤 같은 명령어를 다시 시도할 수 있는 예외 범주로 쓰일 수 있습니다. |
| 인터럽트 | 타이머나 장치처럼 현재 명령어 밖의 원인이 비동기적으로 알리는 사건입니다. |
| ABI | 이진 수준의 호출 규약, 레지스터 사용, 자료 배치와 시스템 호출 경계를 정의합니다. |
| 특권 명령어 | 허용된 특권 모드에서만 실행할 수 있는 명령어입니다. |
| 타이머 인터럽트 | 커널이 주기적 또는 예약 시점에 제어를 얻도록 하는 타이머 사건입니다. |
| 선점 | 현재 실행 주체가 자발적으로 끝내지 않아도 스케줄러가 CPU를 회수하는 동작입니다. |

## 프로세스와 스케줄링

| 용어 | 이 가이드에서 사용하는 뜻 |
|---|---|
| 프로그램 | 저장장치에 있는 실행 코드와 초기 데이터입니다. |
| 프로세스 | 주소 공간, 자격 정보와 커널 객체 참조를 묶은 실행 단위입니다. |
| 스레드 | 레지스터, 스택과 스케줄링 상태를 가진 CPU 실행 단위입니다. |
| 주소 공간 | 한 프로세스가 볼 수 있는 가상 주소와 매핑의 집합입니다. |
| PCB | 프로세스 상태를 설명하는 개념적 제어 블록입니다. 실제 구조체 이름과 정확히 같지 않을 수 있습니다. |
| TCB | 스레드의 레지스터와 스케줄링 상태를 설명하는 개념적 제어 블록입니다. |
| 문맥 전환 | 한 실행 주체의 CPU 상태를 저장하고 다른 주체의 상태를 복원하는 메커니즘입니다. |
| 모드 전환 | 같은 실행 주체가 사용자 모드와 커널 모드 사이를 오가는 사건입니다. 문맥 전환과는 별개입니다. |
| 실행 가능 | CPU를 받으면 실행할 수 있는 상태입니다. |
| 실행 중 | 현재 CPU에서 명령어를 실행하는 상태입니다. |
| 대기 또는 차단 | I/O, 타이머, 잠금 또는 조건 사건이 필요해 CPU를 받아도 진행할 수 없는 상태입니다. |
| 실행 가능 큐 | 스케줄러가 실행 후보를 보관하는 논리적 자료구조입니다. 실제 구현은 단순 FIFO가 아닐 수 있습니다. |
| CPU 버스트 | 한 작업이 블록되기 전까지 연속으로 CPU를 사용하는 구간입니다. |
| 반환 시간 | 최초 도착부터 완료까지의 시간입니다. |
| 대기 시간 | 실행 가능 상태에서 CPU를 기다린 시간입니다. 실습의 단순 모델에서는 반환 시간에서 버스트를 뺍니다. |
| 응답 시간 | 최초 도착부터 처음 CPU를 받을 때까지의 시간입니다. |
| 처리량 | 단위 시간에 완료한 작업 수입니다. |
| 시간 할당량 또는 퀀텀 | 선점형 정책에서 한 번에 허용하는 최대 CPU 실행량입니다. |
| 기아 | 다른 작업은 진행하지만 특정 작업이 정책상 무기한 선택되지 않을 수 있는 상태입니다. |
| 노화 | 오래 기다린 작업의 실효 우선순위를 높여 기아를 완화하는 정책입니다. |
| CPU 친화도 | 한 작업을 특정 CPU에 유지해 지역성을 활용하거나 배치를 제한하는 성질입니다. |
| 부하 분산 | 여러 CPU의 실행 가능 작업량을 재배분하는 정책입니다. |

## 동시성과 동기화

| 용어 | 이 가이드에서 사용하는 뜻 |
|---|---|
| 동시성 | 여러 작업의 진행 구간이 겹치며 순서 조정이 필요한 상태입니다. 실제 동시 실행과 동일하지 않습니다. |
| 병렬성 | 여러 CPU나 실행 장치에서 실제로 같은 시간에 계산하는 상태입니다. |
| 실행 교차 | 여러 실행 흐름의 단계가 하나의 전체 순서로 섞인 결과입니다. |
| 경쟁 조건 | 결과의 정확성이 보장되지 않은 사건 순서에 의존하는 상태입니다. |
| 데이터 경쟁 | 언어 메모리 모델이 정의하는 상충 접근에 동기화가 없는 상태입니다. C에서는 정의되지 않은 동작을 일으킵니다. |
| 원자적 연산 | 다른 관측자가 중간 상태를 볼 수 없는 하나의 연산으로 취급됩니다. |
| 읽기-수정-쓰기 | 읽기, 계산과 쓰기를 하나의 원자적 연산으로 결합합니다. |
| 메모리 순서 | 여러 메모리 접근이 다른 실행 주체에 보이는 순서를 제약하는 계약입니다. |
| 선행 발생 | 한 사건의 효과가 다른 사건보다 논리적으로 앞선다고 보장하는 메모리 모델의 happens-before 관계입니다. |
| 획득 | 대응하는 공개 이전의 효과를 이후 접근보다 앞에 보이게 하는 소비 측 순서입니다. |
| 해제 | 이전 접근의 효과를 공개 연산보다 뒤로 넘기지 않는 생산 측 순서입니다. |
| 순차 일관성 | 관련 원자적 연산이 하나의 전역 순서를 가진 것처럼 보이는 강한 모델입니다. |
| 임계 구역 | 공유 불변식을 읽고 갱신하는 동안 상호 배제가 필요한 코드 구간입니다. |
| 뮤텍스 | 소유권이 있는 상호 배제를 제공하는 동기화 도구입니다. |
| 스핀락 | 획득에 실패하면 잠들지 않고 반복해서 확인하는 잠금입니다. |
| 세마포어 | 제한된 허가 수를 획득하고 반납하는 동기화 도구입니다. |
| 조건 변수 | 뮤텍스로 보호되는 조건식이 바뀔 가능성을 대기자에게 알리는 동기화 도구입니다. |
| 모니터 | 공유 상태, 그 연산, 상호 배제와 조건 큐를 하나로 묶은 추상화입니다. |
| 배리어 | 정해진 참가자가 한 단계에 모두 도착할 때까지 다음 단계 진행을 막는 동기화 도구입니다. |
| 허위 깨우기 | 조건식이 참이라는 보장 없이 조건 대기에서 반환할 수 있는 상황입니다. |
| 깨우기 손실 | 조건 검사와 대기 등록이 원자적으로 연결되지 않아 필요한 알림을 놓치는 오류입니다. |
| 거짓 공유 | 논리적으로 다른 변수가 같은 캐시 라인에 있어 CPU 사이에 일관성 트래픽을 만드는 현상입니다. |
| 무잠금 | 시스템 전체에서는 어떤 연산인가가 계속 완료됨을 목표로 하는 진행 보장입니다. |
| 무대기 | 각 연산이 유한한 단계 안에 완료됨을 목표로 하는 진행 보장입니다. |

## 데드락과 진행

| 용어 | 이 가이드에서 사용하는 뜻 |
|---|---|
| 데드락 | 실행 주체 집합이 서로 필요한 자원을 기다려 외부 개입 없이 진행하지 못하는 상태입니다. |
| 보유 후 대기 | 자원을 보유한 채 다른 자원을 기다리는 조건입니다. |
| 순환 대기 | 자원 대기 간선이 순환을 이루는 조건입니다. |
| 대기 그래프 | 프로세스 간 대기 관계를 간선으로 표현한 그래프입니다. |
| 안전 상태 | 앞으로 요청할 수 있는 최대 자원량까지 고려해도 모든 작업을 마칠 순서가 남는 상태입니다. |
| 불안전 상태 | 모든 작업을 마칠 안전 순서를 보장할 수 없는 상태이며, 현재 데드락이라는 뜻은 아닙니다. |
| 데드락 탐지 | 현재 할당과 미처리 요청에서 완료할 수 없는 집합을 찾는 절차입니다. |
| 데드락 회피 | 새 자원을 할당한 뒤에도 안전 상태가 유지되는지 검사하는 정책입니다. |
| 라이브락 | 실행 주체가 계속 상태를 바꾸지만 서로 방해하거나 양보해 유효한 완료를 만들지 못하는 상태입니다. |
| 희생 작업 | 데드락 복구에서 중단, 되돌리기 또는 자원 회수 대상으로 선택한 작업입니다. |
| 우선순위 역전 | 높은 우선순위 작업이 낮은 우선순위 작업이 보유한 자원을 기다리며 중간 작업에 간접적으로 밀리는 상황입니다. |

## 가상 메모리

| 용어 | 이 가이드에서 사용하는 뜻 |
|---|---|
| 가상 주소 | 프로세스가 명령어에서 사용하는 논리적 주소입니다. |
| 물리 주소 | 메모리 시스템이 물리 프레임이나 장치를 식별하는 주소입니다. |
| 페이지 | 가상 주소 공간을 나눈 고정 크기 단위입니다. |
| 프레임 | 물리 메모리를 페이지 크기로 나눈 단위입니다. |
| 버디 할당기 | 크기가 2의 거듭제곱인 빈 블록을 분할하고 짝 블록과 병합하는 페이지 할당기 계열입니다. |
| 슬랩 또는 객체 캐시 | 페이지를 같은 크기의 커널 객체 칸으로 나누어 재사용하는 할당기 계열입니다. |
| VPN | 가상 페이지 번호입니다. 가상 주소에서 오프셋을 제외한 부분입니다. |
| PFN | 페이지 프레임 번호입니다. 물리 프레임을 식별합니다. |
| 페이지 테이블 | 가상 페이지를 물리 프레임과 접근 권한에 매핑하는 구조입니다. |
| PTE | 한 가상 페이지의 프레임, 존재 여부와 접근 권한을 담는 페이지 테이블 항목입니다. |
| 다단계 페이지 테이블 | 실제로 쓰는 주소 범위에만 하위 테이블을 만들어 희소한 주소 공간의 비용을 줄이는 구조입니다. |
| TLB | 최근 주소 변환과 접근 권한을 캐시하는 변환 색인 버퍼입니다. |
| TLB 무효화 전파 | 페이지 테이블을 바꾼 뒤 다른 CPU의 오래된 TLB 항목을 무효화하는 협력 절차입니다. |
| ASID | TLB 항목이 어느 주소 공간 소속인지 구분하는 아키텍처별 식별자 범주입니다. |
| 페이지 폴트 | 주소 변환이나 접근 권한 처리에 커널 개입이 필요한 동기 사건입니다. |
| 보호 폴트 | 매핑은 있지만 접근 종류가 권한을 위반한 폴트입니다. |
| 요구 페이징 | 페이지를 첫 접근 시점까지 상주 메모리에 올리지 않는 정책입니다. |
| 요구 시 0 초기화 | 첫 접근에서 0으로 채운 프레임을 제공하는 지연 할당 방식입니다. |
| COW | 쓰기 전까지 프레임을 공유하고 쓰기 폴트에서 복사하는 쓰기 시 복사 방식입니다. |
| 상주 | 페이지가 현재 물리 메모리 프레임에 연결된 상태입니다. |
| 익명 페이지 | 파일을 직접 원본으로 갖지 않는 힙, 스택 등의 메모리 페이지입니다. |
| 파일 기반 페이지 | 실행 파일이나 매핑된 파일 내용에서 다시 가져올 수 있는 페이지입니다. |
| 수정 상태 페이지 | 메모리에서 수정되어 원본 저장소와 내용이 달라진 페이지입니다. |
| 페이지 교체 | 메모리 압박에서 회수할 상주 페이지를 선택하는 정책입니다. |
| 작업 집합 | 최근 구간에 한 작업이 활발히 사용하는 페이지 집합입니다. |
| 스래싱 | 작업 집합이 메모리에 맞지 않아 유효 계산보다 폴트와 페이지 이동에 시간을 쓰는 상태입니다. |
| 스왑 | 익명 페이지 등을 메모리 밖에 보관하기 위한 보조 저장 영역입니다. |
| 대형 페이지 | 기본 페이지보다 큰 변환 단위입니다. TLB가 포괄하는 범위를 늘리고 페이지 테이블 비용을 줄일 수 있지만 단위가 거칠어집니다. |

## 파일시스템과 영속성

| 용어 | 이 가이드에서 사용하는 뜻 |
|---|---|
| 경로명 | 디렉터리 이름 구성 요소로 파일을 찾는 문자열 표현입니다. |
| 디렉터리 항목 | 한 디렉터리의 이름을 inode 또는 파일 객체에 연결하는 메타데이터입니다. |
| Inode | 파일 형식, 크기, 접근 권한과 데이터 위치를 나타내는 이름과 분리된 객체입니다. |
| 파일 디스크립터 | 프로세스의 디스크립터 테이블에서 열린 파일 상태를 가리키는 작은 정수 식별자입니다. |
| 열린 파일 기술 | 현재 오프셋과 열기 플래그를 가진 커널의 열린 파일 상태입니다. |
| 하드 링크 | 같은 inode에 다른 디렉터리 항목 이름을 추가하는 연결입니다. |
| 블록 | 파일시스템과 저장장치 I/O에서 사용하는 고정 크기 단위입니다. |
| Extent | 연속 블록 범위를 시작 위치와 길이로 표현한 메타데이터입니다. |
| 슈퍼블록 | 파일시스템 형식, 크기와 루트 위치 같은 전역 메타데이터입니다. |
| 페이지 캐시 | 파일 데이터 페이지를 메모리에 보관하는 커널 캐시입니다. |
| 쓰기 반영 | 캐시에 있는 수정 상태 데이터를 원본 저장장치에 반영하는 작업입니다. |
| 영속성 | 성공으로 확정한 데이터가 요구한 장애 뒤에도 남는 성질입니다. |
| 비정상 종료 일관성 | 갑작스러운 중단 뒤 파일시스템이 허용된 구조 상태로 복구되는 성질입니다. |
| 저널 | 원래 위치에 적용하기 전 변경과 커밋을 기록해 복구를 돕는 로그입니다. |
| 선행 쓰기 로그 | 실제 대상보다 먼저 복구에 필요한 로그를 영속 저장하는 원칙입니다. |
| 체크포인트 | 로그의 변경이 원래 위치에 반영된 지점을 기록해 복구 범위를 줄이는 절차입니다. |
| `fsync` | 특정 파일의 변경을 동기화하도록 요청하는 인터페이스입니다. 정확한 범위는 운영체제의 동작 규칙을 확인해야 합니다. |
| 원자적 이름 바꾸기 | 이름 공간에서는 이전 이름 또는 새 이름 중 하나만 보이게 하는 성질입니다. 비정상 종료 뒤의 영속성과는 별개입니다. |

## 장치 I/O

| 용어 | 이 가이드에서 사용하는 뜻 |
|---|---|
| 장치 컨트롤러 | 명령, 상태와 데이터 이동을 관리하는 하드웨어 또는 펌웨어 인터페이스입니다. |
| 드라이버 | 커널의 공통 I/O 인터페이스와 장치별 명령을 연결하는 소프트웨어입니다. |
| MMIO | 장치 레지스터를 메모리 주소 공간에 매핑해 접근하는 메모리 매핑 I/O입니다. |
| 프로그램 제어 I/O | CPU가 직접 장치 레지스터와 데이터를 주고받는 방식입니다. |
| 폴링 | CPU가 완료 상태를 반복 확인하는 방식입니다. |
| DMA | 장치가 CPU 대신 메모리와 데이터를 주고받는 직접 메모리 접근 방식입니다. |
| DMA 주소 | 장치가 메모리 전송에 사용하는 주소입니다. CPU 물리 주소와 같다고 가정할 수 없습니다. |
| IOMMU | 장치가 보는 I/O 주소를 물리 메모리에 매핑하고 접근을 격리하는 장치입니다. |
| 디스크립터 | 장치 명령, 버퍼 주소, 길이와 플래그를 담는 메타데이터입니다. |
| 링 버퍼 | 생산자와 소비자 색인이 순환하는 고정 크기 디스크립터 큐입니다. |
| 도어벨 | 새 명령이 제출됐음을 장치에 알리는 레지스터 또는 신호입니다. |
| 분산-수집 I/O | 여러 메모리 구간을 하나의 논리적 I/O로 장치에 전달하는 방식입니다. |
| 바운스 버퍼 | 장치 주소나 정렬 제한을 맞추려고 중간에 사용하는 복사 버퍼입니다. |
| 인터럽트 완화 | 사건마다 인터럽트를 내지 않고 시간이나 일괄 처리 기준으로 묶어 알리는 정책입니다. |
| 역압 | 이후 단계의 처리 용량이 부족할 때 앞 단계의 제출 속도를 제한하는 제어입니다. |
| 늦은 완료 | 시간 제한이나 취소 판정 뒤 하드웨어 완료가 도착하는 사건입니다. 버퍼 수명과 중복 완료 처리가 필요합니다. |
