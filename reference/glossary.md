# 용어

- **브랜치**: 하나의 학습 결과와 종료 능력을 가진 독립 과정이다.
- **업무 트랙**: 특정 직무·프로젝트에 진입하기 위해 여러 브랜치를 선택한 경로다.
- **공통 기반**: 여러 트랙에서 반복해 사용하는 변경·문제 해결·시스템 관찰 능력이다.
- **필수 의존성**: 현재 브랜치의 핵심 문서와 실습이 전제로 하는 지식이다.
- **권장 의존성**: 먼저 완료하면 좋지만 필요한 절만 참조하며 진행할 수 있는 지식이다.
- **연결 브랜치**: 직접 선행은 아니지만 실제 업무에서 자주 계약을 주고받는 분야다.
- **심화 브랜치**: 현재 트랙의 프로젝트 진입 능력 이후 특정 내부구조나 규모 문제를 깊게 다룬다.
- **소유 범위**: 해당 브랜치가 상세 설명, 실습과 기준 검증을 책임지는 문제 영역이다.
- **비소유 범위**: 인접 브랜치가 정본을 소유하며 현재 브랜치는 필요한 접점만 설명하는 영역이다.
- **종료 능력**: 문서를 읽었다는 상태가 아니라 실제로 구현·검증할 수 있는 작업이다.
- **브랜치 완료**: 한 브랜치의 소유 범위와 종료 능력을 설명·실습·누적 종료 근거로 확인한 상태다.
- **트랙 완료**: 목표 업무의 필수 브랜치들을 연결해 트랙의 종료 작업을 시도할 준비가 된 상태다.
- **품질 프로필**: 분야에 따라 강하게 요구되는 근거의 형태다. 브랜치 종류와 별개이며 모델·이론, 구현·애플리케이션, 운영·보안, 데이터·ML, 하드웨어·그래픽스가 있다.
- **완성 목표 계약**: 구현 순서와 무관하게 `main`이 먼저 선언한 브랜치의 최종 구조 역할, 소유 경계, 종료 능력과 트랙 위치다.
- **`stable`**: 완성 목표 계약을 사람이 승인해 `main` 카탈로그에 등재한 상태다. 원격 브랜치 존재나 실제 구현 완료를 증명하지 않는다.
- **프로젝트 기여**: 기존 코드베이스에서 작은 기능 또는 버그 수정을 독립적으로 완성하는 수준이다.
- **하위 시스템 소유**: 모호한 문제를 설계·마이그레이션·배포·운영·복구까지 책임지는 수준이다.
- **도메인 리드**: 여러 팀의 기술 기준과 방향을 만들고 조직 수준의 위험을 줄이는 수준이다.
