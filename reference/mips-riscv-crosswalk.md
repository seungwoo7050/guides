# MIPS와 RISC-V 개념 대응표

이 문서는 MIPS에서 익힌 개념을 RISC-V 본문과 연결하기 위한 보조 자료입니다. 이름이 비슷하더라도 인코딩, ABI와 예외 규칙까지 같은 것은 아닙니다. 실제 코드를 작성할 때는 사용하는 ISA 개정판과 ABI 문서를 우선하세요.

## 공통적인 RISC 관점

두 ISA 계열은 다음 학습 주제를 설명하기에 적합합니다.

- 레지스터 간 산술과 적재·저장 분리
- 고정 폭 명령어 인코딩의 필드 분해
- 즉시값 확장
- PC와 분기 대상 계산
- 레지스터 파일, ALU와 메모리를 잇는 데이터패스
- 5단계 파이프라인의 데이터·제어 위험

다만 실제 RISC-V 구현이 반드시 5단계인 것은 아니며, MIPS 제품도 수업에서 다루는 단순 파이프라인과 같지 않습니다.

## 레지스터 이름

| 역할 | 고전 MIPS 표기 | RISC-V ABI 표기 | 주의점 |
|---|---|---|---|
| 0 | `$zero` / 0번 레지스터 | `x0` / `zero` | 쓰기 결과를 버리는 점은 유사합니다. |
| 반환값 | `$v0`, `$v1` | `a0`, `a1` | 시스템 호출 규약까지 같은 것은 아닙니다. |
| 인자 | `$a0`~`$a3` | `a0`~`a7` | 레지스터 개수와 ABI 배치가 다릅니다. |
| 임시값 | `$t0`~`$t9` | `t0`~`t6` | 호출자가 보존하는 레지스터 집합이 정확히 같지 않습니다. |
| 보존값 | `$s0`~`$s7` | `s0`~`s11` | 피호출자가 보존할 범위는 ABI로 확인해야 합니다. |
| 스택 포인터 | `$sp` | `sp` / `x2` | 스택 정렬 규칙이 ABI마다 다릅니다. |
| 반환 주소 | `$ra` | `ra` / `x1` | 호출 명령어의 인코딩과 동작이 다릅니다. |

숫자 레지스터 이름과 ABI 별칭을 섞으면 코드 검토에서 값의 용도가 흐려질 수 있습니다. 함수 코드에서는 ABI 이름을 사용하고, 인코딩을 설명할 때 숫자 이름을 함께 적는 편이 낫습니다.

## 대표 명령어 대응

| 의도 | MIPS 예 | RISC-V 예 | 차이 |
|---|---|---|---|
| 레지스터 덧셈 | `add $t0,$t1,$t2` | `add t0,t1,t2` | 오버플로 트랩 여부를 명령어별로 확인해야 합니다. |
| 순환 덧셈 | `addu $t0,$t1,$t2` | `add t0,t1,t2` | RV32I `add`는 XLEN의 하위 비트를 남깁니다. |
| 즉시값 덧셈 | `addi $t0,$t1,4` | `addi t0,t1,4` | 즉시값 필드는 둘 다 부호가 있지만 인코딩은 다릅니다. |
| 워드 적재 | `lw $t0,8($sp)` | `lw t0,8(sp)` | 정렬과 예외의 세부 규칙이 다를 수 있습니다. |
| 워드 저장 | `sw $t0,8($sp)` | `sw t0,8(sp)` | 소스·기준 레지스터 역할은 유사합니다. |
| 같을 때 분기 | `beq $t0,$t1,L` | `beq t0,t1,L` | PC 상대 오프셋의 인코딩이 다릅니다. |
| 무조건 점프 | `j L` | `jal x0,L` | RISC-V는 `jal`의 목적지를 `x0`으로 지정해 반환 주소를 버립니다. |
| 레지스터 점프 | `jr $ra` | `jalr x0,0(ra)` | RISC-V는 기준 레지스터와 즉시값을 더하는 형태입니다. |
| 상위 즉시값 | `lui $t0,imm` | `lui t0,imm` | 즉시값 배치와 재배치 규칙이 다릅니다. |

`move`, `li`, `nop`, `ret` 같은 표기는 어셈블러 의사 명령어일 수 있습니다. 명령어 수나 인코딩을 계산할 때는 어셈블러가 실제로 무엇을 생성하는지 확인해야 합니다.

## 명령어 형식 비교

고전 MIPS32 설명에서는 명령어 형식을 흔히 R·I·J로 나눕니다.

```text
R: opcode | rs | rt | rd | shamt | funct
I: opcode | rs | rt | immediate
J: opcode | target
```

RV32I는 R·I·S·B·U·J 형식을 사용합니다.

```text
R: funct7 | rs2 | rs1 | funct3 | rd | opcode
I: immediate | rs1 | funct3 | rd | opcode
S: immediate split | rs2 | rs1 | funct3 | immediate split | opcode
B: branch immediate split | rs2 | rs1 | funct3 | immediate split | opcode
U: upper immediate | rd | opcode
J: jump immediate split | rd | opcode
```

RISC-V에서 저장 명령어와 분기 명령어의 즉시값이 여러 필드에 나뉜 이유를 외우기보다 다음 설계 목표를 확인하세요.

- 레지스터 필드의 위치를 여러 형식에서 가능한 한 유지합니다.
- `opcode`와 `funct` 필드로 명령어 해독을 구성합니다.
- 즉시값 비트를 다시 조립하고 부호 확장합니다.

## 분기와 지연 슬롯

고전 MIPS 설명에서는 분기 또는 점프 뒤의 명령어 하나가 실행되는 **분기 지연 슬롯**을 볼 수 있습니다. 그러나 MIPS 개정판과 구현에 따라 세부 규칙이 다르며, 최신 도구 모음에서는 지연 슬롯을 감추거나 다른 형태로 다룰 수 있습니다.

RISC-V 기본 ISA에는 아키텍처가 보장하는 분기 지연 슬롯이 없습니다. 실제로 분기했을 때 잘못 가져온 명령어를 실행하지 않도록 파이프라인을 비우거나 추측 상태를 복구해야 합니다.

따라서 다음 두 문장을 섞지 마세요.

```text
ISA가 다음 명령어 실행을 보장합니다.
마이크로아키텍처가 잘못 가져온 명령어를 내부에서 버립니다.
```

첫 문장은 아키텍처의 지연 슬롯이고 두 번째는 파이프라인 구현입니다.

## 오버플로와 트랩

MIPS의 `add`와 `addi`는 부호 있는 오버플로 예외를 일으키는 명령어인 반면, `addu`와 `addiu`는 트랩을 일으키지 않는 형태입니다. 이름의 `u`가 피연산자를 부호 없는 값으로만 해석한다는 단순한 뜻은 아닙니다.

RV32I의 `add`와 `addi`는 오버플로 예외 없이 하위 32비트를 남깁니다. 부호 있는 오버플로를 확인해야 하는 소프트웨어는 피연산자와 결과를 이용해 별도로 판정할 수 있습니다.

`Tiny-RISC`의 `add`, `addi`, `sub`도 트랩을 일으키지 않고 하위 32비트를 남깁니다.

## 적재 지연과 전달 경로

일부 고전 MIPS 파이프라인 설명은 적재 결과를 바로 다음 명령어에서 사용할 수 없는 적재 지연을 아키텍처 또는 구현 관점에서 다룹니다. 수업용 모델을 실제 모든 MIPS CPU의 동작으로 일반화해서는 안 됩니다.

이 가이드의 파이프라인 모델은 다음과 같이 정합니다.

```text
ALU 결과: 전달 경로를 통해 다음 EX에 바로 전달할 수 있습니다.
적재 결과: MEM 뒤에 생기므로 바로 다음 소비자는 한 사이클 정지합니다.
```

이는 위험 요소를 설명하기 위한 전형적인 5단계 모델일 뿐 RISC-V ISA의 요구사항은 아닙니다. 실제 프로세서는 더 깊은 파이프라인, 비순차 실행, 추측 적재와 재실행을 사용할 수 있습니다.

## 시스템 호출과 ABI 분리

교육용 모의 실행기에서 `syscall` 또는 `ecall`에 특정 번호를 넣어 출력하는 예제를 볼 수 있습니다. 번호와 인자 레지스터는 다음 요소에 따라 달라질 수 있습니다.

- 모의 실행기의 자체 규약
- 운영체제 ABI
- ISA ABI
- 실행 환경 또는 표준 라이브러리

MIPS 모의 실행기의 출력 시스템 호출 번호를 RISC-V Linux에 그대로 적용하거나 그 반대로 적용해서는 안 됩니다. 일반 애플리케이션에서는 가능하면 C 라이브러리나 운영체제의 공식 시스템 호출 ABI를 사용하세요.

## 수업 문제를 옮길 때의 순서

MIPS 문제를 RISC-V 관점으로 다시 풀 때는 다음 순서가 안전합니다.

1. 원문이 요구하는 계산과 메모리 배치를 먼저 적습니다.
2. 각 레지스터의 역할과 수명을 정합니다.
3. 의사 명령어를 실제 명령어열로 확장합니다.
4. 분기 목적지와 즉시값 범위를 다시 계산합니다.
5. ABI가 필요한 함수라면 호출자·피호출자 보존 레지스터를 다시 배정합니다.
6. 분기 지연 슬롯 가정을 제거하고 파이프라인 위험 요소는 별도로 분석합니다.
7. 오버플로와 정렬되지 않은 접근의 예외 규칙을 사용하는 ISA 문서에서 확인합니다.

## Tiny-RISC와의 관계

| Tiny-RISC | MIPS/RISC-V와 닮은 점 | 의도적으로 생략한 것 |
|---|---|---|
| `r0` | 0번 레지스터 | ABI 이름과 전체 레지스터 집합 |
| `add`, `sub` | 레지스터 간 ALU 연산 | 이진 인코딩과 `funct` 필드 |
| `addi` | 부호 있는 즉시값 연산 | 즉시값의 폭 제한 |
| `lw`, `sw` | 기준 레지스터와 오프셋을 이용한 적재·저장 | 캐시, 예외 처리기와 MMU 연결 |
| `beq`, `bne` | 조건 분기 | PC 상대 바이트 인코딩 |
| `j` | 무조건 제어 이전 | 링크 레지스터와 호출 규약 |
| `halt` | 모의 실행기 정지 | 실제 ISA의 특권 종료 경로 |

`Tiny-RISC` 코드를 실제 어셈블러에 넣어 실행하려고 하지 마세요. 먼저 상태 변화와 의존성을 확인한 뒤 실제 ISA 문법으로 다시 작성해야 합니다.
