# 버전 기준과 재현 환경

이 가이드는 2026년 7월 25일에 다음 기준으로 검증했습니다. ISA와 프로세서 설명서는 계속 개정되므로 숫자나 세부 규칙을 인용할 때는 이 문서의 날짜와 실제로 읽은 판본을 함께 남겨 주세요.

## 문서 기준

| 자료 | 이 가이드 작성 시 확인한 기준 | 사용 범위 |
|---|---|---|
| RISC-V Unprivileged ISA | `v20260120`, 2026년 1월 | ISA와 마이크로아키텍처 구분, 기본 명령과 메모리 모델의 정본 확인 |
| RISC-V Privileged ISA | `v20260120`, 2026년 1월 | 권한, 트랩과 주소 변환의 실제 아키텍처 확인 |
| Intel Software Developer Manual | Intel 문서 페이지 2026년 6월 22일 갱신, SDM PDF 판본 `092` | x86 아키텍처, 시스템 프로그래밍과 성능 감시의 비교 자료 |
| Intel Optimization Reference | 1·2권 판본 `050` | 캐시, SIMD, 분기와 프로세서별 성능 조정 자료 |
| IEEE 754 | IEEE 754-2019 | 이진 부동소수점 필드와 산술 용어 |
| POSIX | Issue 8 온라인 판본 | `clock_gettime`, `pthread`, 정렬 메모리 할당 인터페이스 |

위 판본은 `Tiny-RISC`의 명세가 아닙니다. `Tiny-RISC` 동작은 [별도 명세](../exercises/processor-model/spec/tiny-risc-isa.md)에 고정되어 있습니다.

## 실행 도구 기준

필수 범위는 다음과 같습니다.

```text
Python >= 3.12
C11을 지원하는 C 컴파일러
POSIX shell
make
POSIX 스레드
clock_gettime
```

검증 환경에서 사용한 컴파일러 버전은 결과를 만든 장비에 따라 다릅니다. `make verify`는 GCC와 Clang을 구분해 벡터화 진단 선택 사항을 고르고, 알 수 없는 컴파일러에서는 실행 파일의 정확성만 확인합니다.

다음 명령으로 현재 환경을 기록하세요.

```sh
python3 --version
cc --version
make --version
uname -a
```

Linux에서 하드웨어 계수기를 사용한다면 다음도 기록하세요.

```sh
perf --version
cat /proc/sys/kernel/perf_event_paranoid
```

macOS에는 Linux `perf`가 기본 제공되지 않습니다. Instruments, `sample`, 컴파일러가 생성한 어셈블리와 벤치마크 분포처럼 해당 환경에서 지원되는 증거를 사용해야 합니다.

## 재현성이 보장되는 것

자동 검사가 고정하는 결과는 다음과 같습니다.

- 고정 폭 정수의 비트 패턴과 오버플로 판정
- Tiny-RISC 레지스터·메모리·분기 상태
- 단순 5단계 파이프라인의 정지·비우기 횟수
- 캐시 모의 실행기의 적중, 3C 실패와 수정 블록 반영
- TLB 적중, 페이지 폴트, 권한 폴트와 무효화
- MESI 모의 실행기의 상태와 무효화
- C 예제의 체크섬과 스레드 계수기

## 환경에 따라 달라지는 것

다음 결과는 정답으로 고정하지 않습니다.

- 벤치마크 실행 시간과 두 판본의 비율
- 컴파일러가 선택한 정확한 명령열
- 벡터 폭과 반복문 펼치기 계수
- 분기·캐시 하드웨어 계수기의 사건 지원 여부
- 스레드 배치와 거짓 공유의 시간 차이
- CPU 주파수, 열 제한과 미리 가져오기 동작

성능 결과를 공유할 때는 소스 리비전, 실행 명령, 입력, 컴파일러 선택 사항, 장비 정보와 가공하지 않은 결과를 함께 남겨야 합니다.
