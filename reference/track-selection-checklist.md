# 업무 트랙 선택 점검표

다음 질문에 답한 뒤 `docs/03-career-tracks.md`에서 가장 가까운 트랙 하나를 고른다.

## 만들고 싶은 결과물

- 브라우저에서 사용하는 제품인가
- 서버 API와 업무 데이터를 소유하는가
- 공개 서비스의 배포·관측·복구를 소유하는가
- 여러 팀이 쓰는 공통 플랫폼을 만드는가
- 모바일 기기 기능과 앱 배포를 다루는가
- 데이터를 수집·변환·제공하는가
- 모델을 학습하는가, 기존 모델로 작업 시스템을 만드는가
- 프로세스·메모리·하드웨어에 가까운 코드를 만드는가
- 공격 표면과 방어 경계를 검증하는가

## 현재 깊이

- 기존 저장소의 실행 명령을 스스로 찾을 수 있는가
- 실패를 최소 재현으로 줄일 수 있는가
- 테스트가 무엇을 보장하고 보장하지 않는지 설명할 수 있는가
- 상태와 자원의 소유자를 문서로 적을 수 있는가
- 작은 변경을 리뷰 가능한 커밋으로 제출할 수 있는가

세 개 이상이 어렵다면 공통 개발 역량 트랙을 먼저 진행한다.

## 선택 제한

- 한 번에 주 트랙은 하나만 선택한다.
- 필수 브랜치를 완료하기 전 심화 브랜치를 두 개 이상 시작하지 않는다.
- 이미 경험이 있는 브랜치는 roadmap과 capstone 또는 동등한 누적 최종 실습으로 결손만 확인한다.
- 브랜치 완료 뒤 실제 프로젝트에서 한 번 사용하기 전 다음 분야로 이동하지 않는다.

## 완료를 기록할 때

### 브랜치 완료

- 소유 범위와 종료 능력마다 설명·실습·판단 근거를 찾았는가
- 누적 최종 실습에서 핵심 능력을 함께 사용했는가
- 자동 검사가 보장하지 않는 부분을 직접 설명하거나 사람 검토로 확인했는가
- 비소유 범위와 다음 경로를 구분할 수 있는가

### 트랙 완료

- 필수 브랜치들의 종료 능력을 하나의 목표 업무에 연결할 수 있는가
- 권장·심화 항목을 미완료 필수 항목으로 오해하지 않았는가
- 다음 실제 프로젝트에서 맡을 첫 변경 범위를 정했는가

### 프로젝트 경험

- 실제 요구사항, 기존 상태와 다른 사람의 리뷰를 거쳤는가
- 변경 이후의 사용자·운영·호환성 영향을 확인했는가
- 후속 수정이나 반복 기여에서 배운 경계를 기록했는가

브랜치와 트랙의 완료 표시는 프로젝트 경험을 대신하지 않는다. 자세한 판정 기준은 [`브랜치 품질 계약`](../docs/09-branch-quality-contract.md)을 따른다.
