# Catalog

`branches.json`과 `tracks.json`은 `main`의 브랜치·트랙 문서를 만드는 정형 정본이다. 이 카탈로그는 독자의 경로 선택과 새 브랜치의 범위 설계를 함께 지원한다. 생성된 `docs/01-branch-catalog.md`, `docs/03-career-tracks.md`, `docs/04-dependency-map.md`를 직접 수정하지 않는다.

## `branches.json`

최상위 `schema_version`은 카탈로그 형식의 버전이며 현재 값은 `1`이다. `branches`는 공개 로드맵에 등재한 브랜치 객체의 배열이다.

각 브랜치 객체는 다음 필드를 모두 가진다.

- `id`: Git 브랜치 이름과 같은 고유 ID. 소문자 영숫자와 단일 하이픈 구분만 사용한다.
- `title`: 독자에게 표시할 브랜치 이름.
- `kind`: 저장소 안에서 맡는 역할. 난이도나 이수 순서를 뜻하지 않는다.
  - `common-foundation`: 여러 분야가 공유하는 사고법·시스템 기반
  - `language-entry`: 한 언어로 구현과 검증을 시작하는 진입점
  - `field-entry`: 특정 업무 분야에 처음 진입하는 경로
  - `specialization`: 기반 또는 분야 진입 뒤 깊이를 더하는 전문 경로
- `summary`: 브랜치가 제공하는 학습 결과를 한 문장으로 요약한 설명.
- `requires`: 이 브랜치의 핵심 경로를 시작하기 전에 필요한 **직접 필수 브랜치**. 단순한 도구 사용, 일부 장의 참고 지식 또는 선택 예제 때문에 전체 브랜치를 필수로 올리지 않는다.
- `recommends`: 없어도 시작할 수 있지만 이해·진단·확장에 도움이 되는 권장 선행 또는 인접 기반. 학습 순서를 강제하지 않는다.
- `connects`: 순서와 무관하게 실제 프로젝트에서 자주 협업하는 인접 브랜치.
- `continues_to`: 이 브랜치의 종료 능력을 바탕으로 일반적으로 이어 가는 후속 브랜치.
- `owns`: 이 브랜치가 상세 설명, 실습과 검토 근거를 주로 책임지는 범위.
- `excludes`: 의도적으로 다루지 않거나 다른 브랜치에 주 소유권을 맡기는 범위.
- `exit_capabilities`: 브랜치를 마친 독자가 설명과 수행 결과로 보여 줄 수 있어야 하는 능력.
- `url`: `https://github.com/seungwoo7050/guides/tree/<id>` 형식의 정규 브랜치 URL.
- `status`: 공개 카탈로그에서의 상태. 현재 카탈로그에는 `stable`만 등재한다.

### `stable`의 의미

`stable`은 파일 존재나 스크립트 성공으로 자동 판정하는 값이 아니다. 사람이 [`docs/09-branch-quality-contract.md`](../docs/09-branch-quality-contract.md)의 구조·내용·실습·완성도 기준을 검토하고, 독자가 처음부터 종료 능력까지 따라갈 수 있으며 소유 경계가 인접 브랜치와 합의되었다고 승인해 `main`에 등재한 상태다.

`stable`은 모든 오류가 없거나 내용이 영구히 고정되었다는 뜻도 아니다. 브랜치의 계약이 바뀌면 같은 인간 검토를 거쳐 카탈로그와 생성 문서를 함께 갱신한다. 자동 검사는 JSON 형식, 참조와 생성 결과의 기계적 일관성만 확인하며 교육적 품질이나 실제 완료를 대신 판정하지 않는다.

## `tracks.json`

최상위 `schema_version`은 트랙 형식의 버전이며 현재 값은 `1`이다. `tracks`는 목표 업무별 권장 경로의 배열이다. 트랙은 브랜치의 품질 등급이나 별도 완료 상태가 아니다.

각 트랙 객체는 다음 필드를 모두 가진다.

- `id`: 문서 anchor로도 사용하는 트랙 고유 ID.
- `title`: 독자에게 표시할 트랙 이름.
- `summary`: 트랙의 목표 업무와 도달점을 요약한 설명.
- `common`: 트랙 전체에서 공통으로 사용하는 브랜치. 배열 순서는 권장 진행 순서다.
- `required`: 순서대로 완료할 핵심 브랜치. 각 브랜치의 `requires`는 생성 문서에서 앞에 펼쳐진다.
- `required_any`: 각 내부 배열에서 하나 이상 선택해야 하는 택일 필수 그룹. 선택지는 요약에 표시하며, 각 선택의 의존성 경로도 생성 문서에 따로 펼친다.
- `recommended`: 없어도 핵심 트랙은 시작할 수 있지만 인접 협업·진단에 유용한 브랜치.
- `advanced`: 핵심 트랙 종료 뒤 전문 깊이를 확장하는 브랜치.
- `exit_capabilities`: 트랙 종료 시 여러 브랜치를 연결해 수행할 수 있어야 하는 실제 작업.

`common`, `required`, `required_any`는 필수 수준을 표현하지만 각각의 브랜치 내부 전체를 중복 학습하라는 뜻은 아니다. 이미 가진 능력은 해당 브랜치의 로드맵과 종료 기준으로 사람이 확인한다. `recommended`와 `advanced`는 직접 필수 의존성으로 해석하지 않는다.

## 관계 수정 원칙

- `requires`는 없으면 핵심 학습 자체를 시작할 수 없는 직접 전제에만 사용한다.
- 여러 언어 중 하나처럼 대체 가능한 전제는 단일 `requires`로 강제하지 않고 트랙의 `required_any`로 표현한다.
- 일부 예제 실행에만 필요한 언어나 인접 배경은 `recommends`에 둔다.
- `connects`와 `continues_to`는 탐색 안내이며 의존성 graph의 실선이 아니다.
- 새 브랜치를 추가할 때 고정된 총개수를 맞추지 않는다. 대신 고유 ID, 네 종류의 taxonomy, 유효한 참조와 인간의 `stable` 승인을 유지한다.

## 갱신과 확인

카탈로그를 수정한 뒤 다음을 실행한다.

```sh
python3 scripts/check_catalog.py
python3 scripts/render_catalog.py
python3 scripts/render_catalog.py --check
./verify.sh
```

이 명령들은 카탈로그 구조와 생성 문서의 일관성을 확인한다. 다른 브랜치의 존재나 실제 교육적 완성 여부를 자동으로 증명하려는 절차가 아니다.
