# Save and replay — reference exemplar

## save envelope

- format/schema: input `relay-arena-save` v1; output v2.
- build/content: input records `arena-rules@12`; headless migration preserves this declared content identity while translating stable ids. A production migration must explicitly decide when the content version itself advances.
- profile id: `local-1`.
- checksum: fixture accepts only `fixture-valid-v1`; this is a test marker, not a production checksum algorithm.
- payload owner: profile/save subsystem owns best time, cosmetics, binding/accessibility and result commit ids.

## v1 → v2 migration

| v1 | v2 | conversion/default | invariant | failure/rollback |
|---|---|---|---|---|
| `bestTimeSeconds=51.72` | `best_time_ms=51720` | round seconds × 1000 | null or non-negative integer | invalid type/checksum rejects before publish |
| `skin.default`, `skin.founder-blue` | `cosmetic.player.default`, `cosmetic.player.founder-blue` | contract alias map | every id resolves; no silent deletion | unknown id raises error and preserves previous output |
| `dashKey=LeftShift` | `input_settings.bindings.Dash=LeftShift` | logical action binding | known action/control | invalid mapping requires reset/review path |
| `holdToDash=true` | `input_settings.hold_to_dash=true` | boolean preserved | explicit boolean | malformed field rejected/defaulted by documented schema |
| `subtitle=true` | `accessibility.subtitles=true` | boolean preserved | accessibility setting survives migration | missing coverage is a release issue, not migration success |
| v1 has no commit ledger | `result_commit_ids=[]` | safe default | unique match ids | storage/suspend retry must remain idempotent |

## atomic result/save commit

- idempotency key: match id `match-1` in `result_commit_ids`.
- write: serialize v2 to sibling temporary file, flush, then `os.replace`; malformed input is rejected before writing output.
- failure evidence: public contract places a sentinel at the output path, attempts corrupt migration, and confirms the sentinel remains byte-identical.
- previous generation: the headless function proves failure does not overwrite output but does not maintain a separate long-term backup generation; platform retention/cloud policy needs implementation and failure injection.
- suspend/storage failure: keep result pending and retry the same id. Release evidence currently reports this path failed, so it is a ship blocker.

## replay

- scope: same headless rules, Python implementation, `16667us` step, content/rule fixture and canonical fields.
- ordering: command sequence 1–6 at ticks 1, 4, 12, 30, 45, 70.
- checkpoint hashes generated by the headless runner:
  - tick 30 original/mutant: `62c76488…ab5b` equal.
  - tick 60 original `3ff382b9…2401`, mutant `f9504e8f…8f3e`.
  - tick 90 original `08b46cfd…6d0e`, mutant `ac3e0218…2259`.
- known-bad: change sequence 5 (`Interact core-b`) to invalid `core-missing`; first divergent checkpoint is tick 60, matching fixture expectation.
- excluded: presentation dedupe history, device events, engine physics/thread order and cross-platform floating point.

## Evidence and limits

Normal migration returns schema 2 and `51720`; corrupt input is rejected without overwriting the sentinel. Replay mutant is rejected by first-divergence evidence. Manual review must validate actual platform durability, quota/cloud conflict, backup retention, newer schema behavior and compatibility of an older content identity in a v2 save.
